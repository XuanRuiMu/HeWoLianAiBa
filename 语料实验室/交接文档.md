# 语料实验室 · 交接文档（AI 聊天拟人化任务）

根本目的：在使用 deepseek-flash 的前提下，让 AI 对象的聊天尽可能接近真人——判据只有一个：真实语料里的人在同等情境下会怎么说。不许用量化指标（平均字数、~ 占比、条数比）。一旦用比率做优化目标，AI 就会被推成机械的均值化表达。所以最终的验收方式只能是逐句读原文，判断这句话像不像真人说的，和真人表达的意思是否完全一样或相似。由于本项目有人设画像，有性格，有亲密度，有事件、突发事件等，所以你要先去判断，真实语料中的聊天内容，最有可能发生在本项目这些因素的什么情况下（人设画像是什么，性格是什么......），在此情况下，用deepseek的API进行多次实验验证。比如：
原语料为：
A：我要吃早饭了
B：大中午的你吃早饭？
A：对啊，你吃了吗？
B：我早就吃完了

则你要推测出最有可能的上述的因素，在模拟的真实项目环境中进行测试（注意，真实环境中的API是另一个，不要用真实环境的API，用我提供的！），看看AI输出的怎么样，如：

A：我要吃早饭了（固定问话，不需要改变。A模拟用户，B模拟AI）
AI：我要吃午饭了
A：对啊，你吃了吗？（固定问话，不需要改变。A模拟用户，B模拟AI）
AI：啊？

如果和原语料的输出有较大差别，如果确定了不是人设、性格、亲密度、事件/突发事件等影响，则说明就是AI有问题。请进行下述调研方式，进行调研和优化。

## 调研方式

第 0 步：语料矩阵（不是单个语料）
去找所有的对话的语料。已有一个真是微信私聊语料，但是还不够，还要继续寻找。找到语料后，整理一下，挑选有用的语料。我们的项目是用户和AI对象互聊的项目，所以，比如，如果有的语料是，A说一件事情，B说另外一件事情，A又说另一件事情，且他们之间隔了很长的时间间隔。尽管很真实，但是仍不可能发生在本项目，所以这样的语料就不要了。比如，有的语料是做非常正式严肃的学术探讨，尽管和恋爱没有关系，但是他们若仍属于正常的互相对话，则也算是需要的语料之一（在还原该语料的时候，你要注意人设画像等设置要怎么样才能在本项目中复现该冷门语料）。关键是不限内容、只限形态：

纳入：一对一、连续互聊（不代表必须限制你一句我一句这种，比如你两句我三句，只要是连续的，都可以）、相邻轮相关。正式学术探讨要——但要为它配「什么人设 + 什么阶段 + 什么场景」才能复现。
排除：话题跳跃+长间隔、单向讲述、心理学标签集、模型生成数据。
输出：按场景分类（不是按来源），每场景 ≥15 对。

第 1 步：建「行为类别」基线，不是统计基线
对每个场景，归纳真人回复的**行为类别集合」。例如对方纯分享时，真人类别是：追问细节 / 给反应 / 无关短答。

不用数字，用类别。判据从「像不像这句话」升级为「AI 落没落到真人会用的类别里」——这比我逐句读更稳，也比我之前用的比率更难被糊弄。

第 2 步：全场景病灶普查
用探针法：每个场景设计针对性输入 → 记录 触发输入 / 真人行为 / AI 行为 三要素。

先普查完再修。目的是拿到完整病灶清单，避免打地鼠——因为修一个会改变另一个的命中分布，没有全景就会反复。

第 3 步：病灶分三层，按层修
层	判据	例子
出话层通用缺陷	多人设都有，改出话约束	编造经历抢话、收尾感、每轮追问+调侃
人设层特性缺陷	只有特定型有，改人设句	ENTP 段子手
模型能力上限	探针证明 3 轮都压不动	简写、破碎句

第 4 步：模型上限要「先探后修」
每个病灶动手前，先跑一个廉价探针确认「这个模型能不能做到」。能→修；3 轮都压不动→判定为上限，停手并记录，不再投入。

第 5 步：回归集固化
把探针集、守卫脚本、基线一起入库，每次改动后全跑一遍。这次我删文件时误删过一条有效约束，就是没有回归集兜底。

第 6 步：长程实测
固定 3-4 型跑 20+ 轮连续对话，看人格是否衰减、是否退回无 persona 基线。

## 警告

上一个AI AGENT踩过的坑，按代价排序。下一个 AGENT 先读完再动手：

- **模型可用性先验，别信文档型号**：`deepseek-v4.1-flash` 在网关上 403（不在令牌计划内）；`deepseek-flash` 可用但 RPM 限流极紧（频繁 429/熔断，需 45s/75s 退避）；上一轮 77 探针普查实际跑在 `deepseek-v4-flash`。OpenAI SDK 的 `DEEPSEEK_BASE_URL` 必须带 `/v1` 后缀（`https://token.sensenova.cn/v1`），否则 404。
- **探针抽样必须跨会话**：第一版「每场景取前 20 条」实测全部来自同 1 个会话（寒暄报备 20 条=1 个会话），真人行为分布被单个说话人带偏，报告数字全部作废重算。必须轮取 + 单会话 ≤2 条。
- **程度副词对 LLM 无效**：「偶尔/大多/有时」只会被读成「可以用」，反而放大使用（历史 `~` 事故：实测 26.67%=基线 6.5 倍）。禁令必须直接点名失败形态（写「默认不带问号」，别写「少问」）。
- **许可型句式 = 待执行指令，权重远高于禁令**：「可以用 X」会让模型真去用；举例即模板，给了例句就学生例形态。改完第一层必跑 `npx ts-node scripts/检查出话约束.ts`（守卫就是防这个的，须命中 0）。
- **数字即锚**：「最多5条」会贴着上限凑；「默认一条」同理（且「真人每轮1条」是语料严格 user/assistant 交替的**构造产物**，不是行为证据；LCCC 口径真人中位 2 条）。条数不要写死。
- **加约束前先 grep 同主题**：本轮三次自己打自己——「默认不带问号」 vs 原「答完了再问回去也正常」「要么问细节」；新「别编具体地点」 vs 原「问位置答位置」（后者逼出编造）；xinDong 阶段描述「会想知道对方行程」 vs 出口层禁令（欲望层与出话层对打，只能靠采样抽奖）。冲突要从明面裁决，不是撤一条了事。
- **守卫是诊断工具不是文案指挥棒**：别为让守卫归零改 prompt 语义——本轮把全角引号例句改成无引号枚举过检，约束从词面触发退化成条件句（「凡是顺着对方的话补…」），主动自报直接脱管。
- **A/B 点估计不是结论**：双臂人设其实不同（`shengChengJiaoSe` 每轮 Math.random 生成外貌/家乡/爱好）、单次采样（temperature=1.0）、两臂是相隔一刻钟的不同批次；24 条 Fisher p=0.1365 不显著。追问率/字数只能做退化检测，判据只能是逐句行为类别比对。
