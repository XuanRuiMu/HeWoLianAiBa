## 三、方案（三选一，建议 C）

### A. 最小修复（1 天）
只把 `病灶清单.md` 里三条"未解决"逐条落成**点名失败形态**的约束：
1. 长篇安慰 → 现已有"别把话头转成让他休息/别撑着/早点睡"，但缺"对方只说了累/烦这一个词时，不要分析他为什么累"
2. 观点讨论话多 → 加"对方抛观点时，第一句只表态度（不认同/认同/没想过），不展开论证；对方追问再展开"
3. 咨询类编造 → 现已有"人设里没有的一律没有"，但缺"对方问护肤/健身/考试这类专业问题时，只说自己做过的、不给他没问过的建议"

风险：低。收益：可量化（用 42 条探针跑改前/改后）。

### B. A + 记忆与关系机制（3–5 天）
在 A 基础上，对齐 2026 同类项目已成型的三件事：

1. **记忆可取源**（抄 Mirrai / Utsuwa）：每轮回复在气泡下方折叠显示"这轮想起了哪几条"，数据来自已有的 `关键事件` / `对话摘要` / `承诺兑现`，不改存储，只加一个出参和折叠区。
2. **好感度拆轴 + 因果事件**（抄 Utsuwa）：现四维（信任/亲密/趣味/关怀）只用于算总分，改为四维各自独立展示 + 每次变化写一条 `好感度变化历史`（表已存在），前端给"上次因为什么涨/跌"。
3. **主动开口最小版**（抄 N.E.K.O / Mirrai）：按用户历史活跃时段分布采样，N 小时无互动推一条站内通知，不做推送通道。

风险：中（涉及表结构出参与前端新面板）。收益：解决"AI 永远被动在线"这个陪伴感断点。

### C. B + 用历史语料做一次真受控对照（5–8 天，建议）
1. 从 git 恢复 `语料实验室/`（只恢复到本地、保持 gitignore，不入库）。
2. 用其中的 42/44 条探针 + 14 场景矩阵，跑**改前基线**：记录每条落在哪个行为类别、字数/条数/问号率（仅作退化检测，不作优化目标）。
3. 按 A 改提示词 → 重跑同一批探针 → 只判"类别是否更接近真人"，**不追比率**。
4. 再用 B 的机制改一轮 → 重跑 → 出三臂对照表。
5. 全程本地真模型（`DEEPSEEK_BASE_URL` 指向现有网关，`deepseek-flash`），不 mock。
