# 数据库备份与恢复手册

<!-- 适用：lovewithme PostgreSQL 16（容器 lovewithme-postgres，custom 格式 dump） -->

## 一、备份

### 1.1 脚本备份（推荐）

```bash
bash deploy/备份数据库.sh
```

- 凭据从项目根 `.env` 的 `POSTGRES_USER` / `POSTGRES_PASSWORD` / `POSTGRES_DB` 读取（已有环境变量优先），脚本内无任何硬编码密码。
- 产物落盘到 `备份/postgresql/<库名>_<时间戳>.dump`（custom 格式 `-Fc`，压缩、可选择性恢复）。
- 滚动保留最近 N 份，N 由环境变量 `BEI_FEN_BAO_LIU_FEN_SHU` 控制，默认 `7`；超限自动删最旧。
- 幂等可重复执行；任何一步失败（容器未运行、dump 为空等）均以非零码退出。

### 1.2 手动完整备份命令

```bash
# 在项目根目录执行（Git Bash / Linux）
set -a; . ./.env; set +a
docker exec -e PGPASSWORD="$POSTGRES_PASSWORD" lovewithme-postgres \
  pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc \
  > "备份/postgresql/${POSTGRES_DB}_manual_$(date +%Y%m%d_%H%M%S).dump"
```

### 1.3 定时任务

Linux 宿主机 crontab 示例（每天 03:30 备份一次）：

```cron
30 3 * * * cd /path/to/和我恋爱吧 && /usr/bin/env bash deploy/备份数据库.sh >> 备份/postgresql/备份日志.txt 2>&1
```

Windows 宿主机任务计划示例（管理员 PowerShell，一次性创建）：

```powershell
schtasks /Create /TN "lovewithme数据库备份" /SC DAILY /ST 03:30 /TR "\"D:\Program Files\Git\bin\bash.exe\" -c \"cd '/d/xuanr/Desktop/燃烧之陨我的世界服务端/和我恋爱吧' && bash deploy/备份数据库.sh\""
```

## 二、恢复

> 版本匹配约束：本 dump 由 pg_dump 16.14 生成，pg_restore 必须 ≥ 16.x（建议使用同版本 postgres:16-alpine 镜像内的 pg_restore）。低版本工具读高版本 dump 会报 unsupported version 错误。

### 2.1 前置：停止写入

```bash
docker compose stop backend
```

### 2.2 方式一：docker exec pg_restore 恢复到现有卷

适用于数据卷仍在、需要覆盖恢复的场景：

```bash
set -a; . ./.env; set +a
DUMP="备份/postgresql/<替换为实际文件名>.dump"

# 1) 断开所有连接并重建空库（保留卷）
docker exec lovewithme-postgres psql -U "$POSTGRES_USER" -d postgres \
  -c "SELECT pg_terminate_backend(pid) FROM pg_stat_activity WHERE datname='$POSTGRES_DB' AND pid<>pg_backend_pid();" \
  -c "DROP DATABASE IF EXISTS \"$POSTGRES_DB\";" \
  -c "CREATE DATABASE \"$POSTGRES_DB\" OWNER \"$POSTGRES_USER\";"

# 2) 将 dump 放入容器可见目录后执行恢复
#    （compose 已挂载 ./备份/postgresql:/备份，宿主机文件在容器内 /备份 下直接可见）
docker exec lovewithme-postgres \
  pg_restore -U "$POSTGRES_USER" -d "$POSTGRES_DB" --no-owner --role="$POSTGRES_USER" "/备份/$(basename "$DUMP")"

# 3) 重启后端
docker compose start backend
```

若不想依赖挂载，也可用 stdin 管道：`docker exec -i lovewithme-postgres pg_restore -U "$POSTGRES_USER" -d "$POSTGRES_DB" --no-owner < "$DUMP"`。

### 2.3 方式二：恢复到干净新卷（灾难演练标准流程）

模拟盘坏后从零重建：

```bash
cd 项目根目录

# 1) 记下当前 dump 文件路径，然后彻底停站并删除旧卷
docker compose down -v

# 2) 重新启动一个只有 postgres 的干净环境
docker compose up -d postgres
docker compose exec postgres sh -c 'until pg_isready -U "$POSTGRES_USER"; do sleep 1; done'

# 3) 用临时一次性容器执行恢复（不污染主容器）
docker run --rm \
  --network lovewithme_lovewithme-network \
  -v "$(pwd)/备份/postgresql:/备份":ro \
  -e PGPASSWORD="$POSTGRES_PASSWORD" \
  postgres:16-alpine \
  pg_restore -h postgres -U "$POSTGRES_USER" -d "$POSTGRES_DB" \
  --no-owner --role="$POSTGRES_USER" "/备份/<替换为实际文件名>.dump"

# 4) 启动全部服务
docker compose up -d
```

> 注意：网络名前缀为 compose 项目名（`name: lovewithme`），实际名称以 `docker network ls` 输出为准。

### 2.4 恢复后验证数据一致

```bash
docker exec lovewithme-postgres psql -U lovewithme -d lovewithme -c "\dt"
```

- 表数量应为 **19 张业务表 + schema_migrations 版本表 = 20 张**：用户、角色、消息、好感度、记忆、对话摘要、审计日志、封禁记录、通知、游戏档案、游戏结局、用户人设、反馈、评估、夺舍日志、关键事件、媒体文件、通话记录、协议留痕、schema_migrations。
  （2026.08.25 R6 收尾后：`成就` 等历史残留死表已从基线清除，不再出现；恢复演练已实测通过。）

行数与体积抽查（与备份前的基线对比）：

```sql
SELECT '用户' AS 表, COUNT(*) FROM 用户
UNION ALL SELECT '消息', COUNT(*) FROM 消息
UNION ALL SELECT '角色', COUNT(*) FROM 角色
UNION ALL SELECT '好感度', COUNT(*) FROM 好感度;
SELECT pg_size_pretty(pg_database_size('lovewithme'));
```

- 行数应与故障前一致（可在备份当天先跑一遍上述 SQL 存档作为基线）；库体积应在同一数量级。
- 抽样业务校验：任取一条 `消息` 内容与故障前最后聊天记录比对一致。

### 2.5 校验 dump 文件本身（无需入库）

```bash
docker run --rm -v "$(pwd)/备份/postgresql:/备份":ro postgres:16-alpine \
  pg_restore --list "/备份/<替换为实际文件名>.dump" | head -n 20
```

能列出 TOC 条目即证明 dump 结构完好可用。
