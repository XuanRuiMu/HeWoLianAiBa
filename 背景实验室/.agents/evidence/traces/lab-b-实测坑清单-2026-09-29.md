## 几何/纹理层

16. Grass_chunk 的 geometry.constructor 是裸 BufferGeometry → `new(w,h)` 得到空壳 → Mesh 不可见。
17. PlaneGeometry.clone() 被 bundle 改写 → 同样退化成空 BufferGeometry。
18. 直接复用 `__reveal_mesh__.geometry` 会「吃掉」全屏 reveal 滤镜（22 版事故：整画面紫带白边）。
19. 可行解（26 版在用）：手工复制 donor 的 position/uv/index 数组 → new BufferGeometry → setAttribute/setIndex，零共享、不空壳。
20. 纹理不能在 img.onload 里创建（时序早于 bundle 纹理系统就绪会静默失败）。必须 onload 只存 img，rAF 循环里等 Grass_chunk 就绪后再 new TexCtor(img)。
21. 不能用 Canvas 中转纹理（new TexCtor(canvas) 失败），必须直接 new TexCtor(img)。
22. 吴昊阳可见性开关：depthTest=false + renderOrder=10 才能压过所有草片与地形（24 版首次见效）。
23. 不 clone 也不共享几何时，uColorSpace 实测是 `srgb-linear`（非标准值），说明该 bundle 改写/序列化过颜色空间 → 灰白问题未解（V-01）。

## 第 3 轮（2026-09-29 下午）新增实测坑

> 本轮改用自有工具链（agent-browser 的 Chrome + playwright-core），不再依赖 Chrome MCP。

### 验证环境层

24. **必须"有头 + 真实 GPU"**。无头 + SwiftShader 只有约 3fps，`requestAnimationFrame` 几乎不推进 →
    开场 reveal 动画卡在 `uRevealProgress≈0.006`，整页被遮罩盖住，看起来像"什么都没渲染"，极易误判。
    加 `--ignore-gpu-blocklist --enable-gpu-rasterization` 且 `headless:false` 后恢复 60fps
    （实测 ANGLE / NVIDIA RTX 3050 Ti）。
25. **reveal 完全揭示约需 32 秒**（`revealP` 才到 1）。早于此时截图拍到的是遮罩，不是渲染失败。
26. `exp.engine.renderer` 是**包装对象**（`{sizes,camera,scene,canvas,renderCameraOverride,renderSceneOverride}`），
    没有 `.render`/`.getContext`；真 three 渲染器在 `exp.engine.renderer.instance`。
27. agent-browser 直接 `open` 在本机报 `Chrome exited early without DevToolsActivePort`（需 `--no-sandbox`），
    且其 daemon 会继承 stdout 导致命令看似挂起；改用 playwright-core 自建驱动更可控。

### 场景层（本轮新发现，重要）

28. **相机上挂着一个全屏遮罩 `__reveal_mesh__`**（`MainCamera` 的子节点），
    属性：`transparent:true, depthWrite:true, depthTest:true, renderOrder:999`。
    它**开着深度写入**，会先写入近处深度 → 任何放在天空、且 `depthTest:true` 的东西
    （极光、远景挂件）会被**整片挡掉**。这就是"极光看不见"的真因。
    **解法：把 `revealMesh.material.depthWrite = false`**（它是全屏透明覆盖层，本就不该写深度）。
    注意：直接设一次可能被引擎重置，需在每帧 loop 内保证。
29. 排查遮挡的正确姿势：逐个隐藏 `scene.children` 并截图对比。
    本场景 `scene.children = [CameraGroup, CampfireLight, SunLight, SunLightTarget, SwarmLight,
    __rain_particles, Experience, SunAnchor, __lab_aurora__, __lab_wu_carpet__]`，
    可见内容分散在 `CameraGroup` 与 `Experience` 两处。
30. bundle 用 `new Worker(new URL("/grass-bg/assets/SamplingWorker-CXOyn3RT.js", import.meta.url), {type:"module"})`
    与 `FBM3DWorker-D67YOMzS.js` 加载两个计算 Worker；因服务根目录无 `grass-bg/` 而 404（PAGEERROR ×2）。
    **实测不影响画面**（与上一任基线观感一致）；现有 fetch 改写拦不住 Worker 构造，本轮**未改**，属已知噪音。
31. 人影"趴"的正确姿态：平铺（法线朝上）会被低俯角相机压扁到约 25%，
    竖直立牌又像贴纸。正解是 `faceCamera(mesh, tilt)`：正面朝相机 + 绕相机水平方向后仰 `tilt`，
    实测 `tilt=1.25` 弧度（约 72°）在可辨认与"趴"之间取到平衡。
32. 等比必须显式修正：几何是 2x2 方形、原图 443x312(1.4199:1)，故 `scale.y = scale.x / 1.4199`。
33. 落点用"屏幕取点 → 相机射线打 main-island"反求世界坐标最稳：
    `new V3(ndcX, ndcY, 0.5).unproject(cam).sub(cam.position).normalize()` + `raycaster.set()`；
    本轮定稿落点 `(2.24, 0.50, 4.05)`（地面 y≈-0.06，抬高让草只遮下半身）。

## 第 4 轮（2026-09-29 晚）新增实测坑（用户给 50 分后返工）

### 验证层（最关键，之前误判过两次）

34. **该站点的渲染是"按需触发"的**：开场动画/揭示结束后引擎不再逐帧重绘。
    此时在运行中改场景对象（`visible=false`、uniform 等）**画布不会更新**，
    截图拿到的是旧帧，会得出"改了没生效"的错误结论。本轮因此误判两次。
    - 判定方法：隔 3 秒连拍两张，md5 相同 = 已停绘。
    - 绕开办法：**用"加载即生效"的 initScript 改状态**（如
      `setInterval(function(){ if(window.__labWuMesh) window.__labWuMesh.visible=false; },80)`），
      让初始渲染就不含该对象；或把验证放在动画仍在进行的时段。
    - 无效办法：改视口尺寸触发 resize（高分辨率有头模式下不生效）。
35. 分辨率会影响停绘时机：1280x720 时 45 秒仍在逐帧重绘，1920x868 时更早停。
36. **窗口被遮挡也会影响**：已加 `--disable-background-timer-throttling /
    --disable-backgrounding-occluded-windows / --disable-renderer-backgrounding /
    --disable-features=CalculateNativeWinOcclusion` 并在建页后 `bringToFront()`。
37. 开场揭示（reveal）**偶发在 60 秒仍未到 1**，同一参数不同次运行结果不同；
    取证前必须 eval 读 `uRevealProgress` 确认为 1，否则会拍到遮罩（表现为画面四周发黑、中间一块有机形状）。

### 颜色空间层

38. **场景里的 `Color.set('#hex')` 会自动做 sRGB→线性 转换**（three 颜色管理默认开）。
    自定义 ShaderMaterial 里若直接把 sRGB 数值写进 uniform，渲染后会被输出编码提亮，
    表现为"明显偏亮发白"。必须手工做 `c<=0.04045 ? c/12.92 : ((c+0.055)/1.055)^2.4`。

### 素材获取层

39. Wikimedia 缩略图 URL **只接受固定档位宽度**（320/640/800/1024/1280/1920/2560…），
    传 1600 会返回 400 `Use thumbnail sizes listed`（且返回的是 HTML，`curl -o x.jpg` 会存成 2KB 的错误页，极易误判"下载失败"）。
    改用 `upload.wikimedia.org/.../原文件名` 直链最稳（但原图可能 8MB+）。

### 几何层

40. **"近直立的人物平面"与"平地"在几何上无法自然衔接**：
    相机俯角只有约 15°，人物平面必须接近直立才能被看清；
    而直立平面与地面之间必然出现缝，硬补一块从轮廓垂到地面的过渡面会形成明显"帆状"突起。
    本轮采用"按轮廓生成垫坡 + 收紧过渡带（margin 1.16 / 模糊 3 次）+ 接触阴影"折中，
    并在 loop 内让补片颜色跟随主题（含 sRGB→线性修正）。
41. 人物开启 `depthTest:true` 后，**前景草会自然遮挡他**（这是用户要的"融合"），
    但草过密/人物过低会把人整个埋掉；本轮把落点抬高到 y=0.50 后才取得平衡。

### 地形/姿态层（用户第二次裁决后确定，最关键）

42. **"平地面 + 斜着的人"必然导致悬空，且补一块过渡面救不了。**
    根本解法是**把地形真正隆起成与身体同角度的坡**，让人躺在坡上。
    只做"轮廓补片"而不改倾角，补片会变成一堵近乎垂直的墙（本轮实测：一块明显"帆状"突起）。
43. **倾角是唯一的关键旋钮**（`WU_TILT`）：
    - 相机俯角只有约 15°，所以 0（平躺）会被压扁到约 26% → 不可辨；
      PI/2（竖直）可辨但悬空感最强。
    - 取 0.68 弧度（约 39°）时，身体长度投影约为真实的 85%（`sin(39°+15°)` 近似），
      可辨性足够，同时坡面是自然草坡。
    - 通用公式：身体沿视线方向被压扁的比例 ≈ `|cos(tilt + 相机俯角)|` 的反向，
      实用判据是 **`sin(tilt + 俯角)` 不宜低于 0.75**。
44. 地面补片的模糊次数要与倾角匹配：倾角越小（越平躺），坡越矮，可以用更宽的 `GROUND_MARGIN`
    和更多次模糊把坡脚与原地形自然衔接；倾角越大，过渡带必须越窄，否则出现"帆"。
