## 一、问题1：403 发送失败（LianAi_012 PERMISSION_DENIED）

### 根因

`backend/src/services/安全审核.ts::shenHeNeiRongAnQuan` 在 AI 审核服务不可用时（DeepSeek 超时/限流/无 key），
本地词库扫描通过后仍返回 `wei_gui: true` + `lei_xing: SHEN_HE_FU_WU_BU_KE_YONG_JIAN`。
`backend/src/routes/消息.ts` 发送接口收到该结果后一律走 403 分支 → 前端归一为 PERMISSION_DENIED → 显示 LianAi_012「这一步还轮不到你」。

角色创建后紧接发消息时，DeepSeek 刚被开场白生成/概率计算占用，审核调用偶发失败 → 偶发 403。
这正是"新会话文本发送偶发 403"的时序根因：不是权限判定误伤，是审核服务降级被当成违规拦截。

### 修复

- `backend/src/routes/消息.ts:437-459`：`SHEN_HE_FU_WU_BU_KE_YONG_JIAN` 时不再进违规分支——
  不记违规、不记 IP 违规、不回 403，消息照常落库（本地词库已扫过，AI 层不可用不等于违规）。
  真实内容违规（`lei_xing` 非审核服务不可用）仍回 403 并记违规，行为不变。
- 对齐 `routes/资料.ts:107` 已有的「审核服务不可用≠用户违规」口径。

### 验收

- `routes/__tests__/消息业务分支.test.ts` 更新断言：审核服务不可用 → 200（放行），真实违规 → 403 不变。
- 该路径不再产生 LianAi_012 误报；真违规仍有 403 明确原因（`xiaoXiNeiRongWeiGui`）。

## 二、问题2：新会话缺 AI 开场消息

### 根因（两层）

1. **概率门控**：`角色生成.ts::baoCunJiaoSe` 原先用 `jiSuanKaiChangBaiGaiLv`（10%~90%）+ `Math.random()` 决定发不发。
   非测试环境兜底概率 0.5 → 约半数新会话无开场消息。
2. **降级缺口**：`开场白生成.ts::shengChengKaiChangBai` 无 AI key / AI 调用失败时抛异常（`ROLE_GENERATION_MODEL_UNAVAILABLE` / `ROLE_GENERATION_MODEL_CALL_FAILED`），
   而 `baoCunJiaoSe` 注释声称"内部 try/catch 失败会降级到 jiangJi 不会抛出"——实际代码没有这个降级，异常直接冒泡导致角色创建失败。

### 修复

- `backend/src/services/角色生成.ts`：删掉概率门控，开场白**必发**；开场白生成/落库失败不阻断角色创建（角色已入库，catch 吞掉）。
  移除 `jiSuanKaiChangBaiGaiLv` 导入。
- `backend/src/services/开场白生成.ts`：
  - 无 AI key / VITEST → 直接 `jiangJiKaiChangBai`（启发式兜底），不再抛异常。
  - AI 调用失败 / JSON 解析失败 → 降级到 `jiangJiKaiChangBai`，不再抛异常。
  - 补上注释声称的 try/catch 降级，代码与文档一致。

### 验收

- 每个新会话必有 AI 开场消息（AI 生成或启发式兜底）。
- 开场白失败不再导致角色创建 500。
