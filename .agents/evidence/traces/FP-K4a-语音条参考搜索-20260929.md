## 一、语音条候选（3 个）

### 候选 1（首推）：TencentCloud/chat-uikit-vue — message-audio.vue

- 链接：https://github.com/TencentCloud/chat-uikit-vue
- 关键源码（已实读验证）：
  - `Vue3/Demo/src/TUIKit/components/TUIChat/message-list/message-elements/message-audio.vue`
  - 同路径 Vue2 版本亦存在（`Vue2/TUIKit/components/.../message-audio.vue`）
- 许可证：Apache-2.0（可商用，署名即可）
- star/维护：217★，81 commits，5 open issues；腾讯官方 IM TUIKit，随 SDK 持续更新
- 技术栈：Vue2 + Vue3 双版本，Vue3 版为 `<script lang="ts" setup>` + SCSS，与本项目 Vue3+TS 完全同构
- 与 QQ/微信的接近点（已逐行核验源码，非推测）：
  1. 左右朝向：`message.flow === 'out'` 加 `reserve` 类 → `flex-direction: row-reverse`，喇叭图标 `rotate(180deg)`，时长文字 `text-align: end`——与微信"己方消息喇叭朝左、对方朝右"完全一致
  2. 声纹播放态动画：`.mask.play` 使用 `animation: audio-play 2s steps(1, end) infinite`，keyframes 在 0%/50%/75% 三档切换 `scaleX(0.7056 → 0.3953 → 0 → hidden)`——即微信喇叭三段圆弧逐级点亮/熄灭的阶梯动画，参数可直接抄用
  3. 时长文字：`{{ data.second || 1 }} "`，与微信 `N"` 格式一致
  4. 气泡宽度随时长缩放：`:style="{ width: ${data.second * 10 + 20}px }"`——微信/QQ 同款"越长越宽"规则，公式可直接复用
  5. 播放互斥：播放新语音前暂停并重置页面上所有 `<audio>`；`ended/pause` 事件复位播放态；`flow === 'in'` 时上报已读（未读红点可挂接）
- 差距：
  1. 声纹形态是"喇叭图标+遮罩阶梯动画"（微信移动端风格），非条状声波 bars；QQ 新版桌面端为喇叭弧+条状混合，需用户裁决以哪种为准
  2. 组件耦合腾讯 IM SDK 的消息模型（`messageItem.flow`、`hasRiskContent`、`setAudioPlayed` 事件），不能整包安装使用，需摘出结构重写为独立组件（工作量小）
  3. 无进度/时间条能力
- 移植工作量：低。单文件 203 行，结构+SCSS 参数直接摘出，替换消息模型为本项目 store 字段即可
- 时间条融合建议：保留 mask 阶梯动画表达"播放中"，在气泡底部叠加一条 2px 进度线（宽度 = `currentTime/duration`），或参考 21st.dev 候选的 progress overlay 方案；播放态与时间条共用同一个 `timeupdate` 驱动

### 候选 2：advanced-chat/advanced-chat-components（原 antoine92190/vue-advanced-chat）

- 链接：https://github.com/advanced-chat/advanced-chat-components ；npm: https://www.npmjs.com/package/vue-advanced-chat
- 许可证：MIT
- star/维护：2081★，pushed_at 2026-09-10，活跃维护，非 archived；Vue 3.5+ typed 组件库（TS 类型完备，有 Storybook）
- 技术栈：Vue3 + TS，与本项目同构，可直接 npm 安装
- 已实读源码验证：
  - `src/components/AudioPlayer.vue`（252 行）：进度条式播放器（mm:ss 时间、scrubbing、hover 进度事件、disabled 态），Telegram 风格
  - `src/components/MessageFile.vue`（288 行）：文件行组件，含图片/视频 MIME 分支预览、下载/预览 action、ProgressBar 上传进度、blur-loading
- 与 QQ/微信的接近点：音频消息、文件消息、消息流左右布局齐全；播放控制工程逻辑成熟（互斥、进度事件、时间格式化）
- 差距：音频气泡不是微信声纹样式（无喇叭弧线动画、无宽度-时长缩放），视觉需完全重写；整体是"通用聊天库"风格而非微信风格
- 移植工作量：中。作为整库引入需吃下其消息模型；只摘 AudioPlayer/MessageFile 的播放控制逻辑则较小
- 时间条融合建议：其 AudioPlayer 已有 `update-progress-time` 事件与 progress 状态机，时间条可直接复用该驱动逻辑，再套微信气泡外观
- 定位：若用户想要"成熟整库打底 + 微信皮肤重写"，此为首选；若只要微信语音条本体，候选 1 更直接

## 四、推荐结论（供用户裁决）

**推荐组合：以候选 1（chat-uikit-vue）为样式/动画参数唯一事实来源 + 候选 2 为工程逻辑参考 + 21st.dev 为时间条交互范式。**

理由：
1. 视觉交互接近度最高：候选 1 是唯一经源码逐行核验、完整实现微信语音条四要素（左右朝向、声纹阶梯播放动画、`N"` 时长文字、宽度随时长缩放公式 `second*10+20px`）的 Vue3+TS 实现，且出自腾讯官方（微信同厂），Apache-2.0 可商用——按筛选优先级（视觉接近度＞成熟度＞可移植性＞许可证）四项全优
2. 本项目为 Vue3+TS+Vite，候选 1 的 Vue3 目录即 `<script lang="ts" setup>`+SCSS，摘出重写为独立组件（剥离 SDK 消息模型）工作量最小、还原度最高
3. 时间条融合路径明确：mask 阶梯动画保留"微信感"，底部叠加进度线或采用 21st.dev 的 progress overlay（已播放声纹高亮）方案；播放驱动复用候选 2 的 `timeupdate`/进度事件模式
4. 文件消息与语音条同仓库同风格体系，一次移植两种消息样式一致，直接满足需求 18/20

**待用户裁决的关键分叉**：声纹形态取"微信喇叭三段弧（候选 1 现状，有精确 CSS 参数）"还是"QQ/新版条状声波 bars（需用 CodePen/CSDN 参考自行调参，无单一权威开源实现）"。需求 18 写"QQ/微信"，两家形态不同，必须用户选定其一或指定混合规则。
