## 2. 根因定位（文件:行号）

机制 = 滚动容器零上内边距 + 下侧三层间距叠加（flex 列布局中 gap 与子项 margin 不合并、逐层相加），**不是 margin 塌陷**（flex 容器内 margin 永不塌陷）。点名链路中间距令牌 var(--jiange-*) 使用次数为 **0**——全部是硬编码字面量：

1. `frontend/src/views/过往战绩.vue:1033` — `.zhanji-liebiao { padding: 0 16px 16px }`：上内边距 0，"默认分类"框贴头。**不一致的主根因**
2. `frontend/src/views/过往战绩.vue:1036` — `gap: 12px`：非令牌档位值
3. `frontend/src/views/过往战绩.vue:1057` — `.jiazai-zhuangtai, .kong-zhuangtai { margin: 8px 4px 4px }`：margin-top 8px 与 gap 12px 叠加（下侧 +8）
4. `frontend/src/components/战绩分类管理.vue:170` — `.fenlei-biao-qian-lan { padding-bottom: 4px }`：标签栏底部再加 4px（下侧 +4；疑为 overflow-x:auto 裁切避让，但无注释说明，且造成不对称）
5. 移动端放大项：`frontend/src/views/过往战绩.vue:2054-2057` — `@media(max-width:640px){ .zhanji-liebiao{ padding-inline:10px } }`：左右 10px 也是硬编码非令牌值
6. 相邻散点：`frontend/src/components/战绩分类管理.vue:157`（gap:10px）、`:166`（gap:8px）、`frontend/src/components/空态.vue:38-39`（gap:8px; padding:32px 16px，本页未消费该组件，但同属硬编码散点）

主代理推断核验：**部分证实、需修正**——"硬编码间距"属实（点名链路 100% 硬编码），但"硬编码与令牌混用"不成立：该链路根本没有令牌参与；且不一致的机制是"上 0 / 下三层叠加(4+12+8)"，非 margin 塌陷。

## 5. 给 K1b 的修复方案建议

### A. 点名问题（根因级）
1. 过往战绩.vue:1033 `padding: 0 16px 16px` → `padding: var(--jiange-zhong)`（上=左右=下=16px，一举消除"上 0"主根因；移动端 2054-2057 的 padding-inline:10px 同步令牌化或注释保留理由）
2. 间距机制二选一收口：块级纵向间距全部交给容器 gap，删除子项叠加 margin——过往战绩.vue:1057 `margin: 8px 4px 4px` → `margin: 0 4px`（保留左右 4px 视觉内缩，删上 8px；下 4px 并入 gap 预算）
3. 战绩分类管理.vue:170 `padding-bottom: 4px`：若为 overflow-x:auto 焦点环/阴影裁切避让则加注释并保留（同时从上间距预算中扣除），否则删除。删除后下间距 = gap 12→16px（令牌化），上下对称
4. gap:12px（:1036）→ var(--jiange-zhong)（16px）或按 §3 决策新增 12px 档后吃新令牌

### B. 全站令牌化收口策略（分批，防一次改崩）
- 批1（本次）：点名链路 3 文件（过往战绩.vue / 战绩分类管理.vue / 空态.vue）
- 批2：高频页面（账号与安全.vue 68 处——等 K2 完成后、主页内容.vue 50 处、聊天页面.vue 87 处）
- 批3：其余长尾 + global.css
- 每批只把"块级区段间距"（容器 padding/gap、区块 margin）令牌化；控件内部微距统一吃新细档令牌；纯几何值（宽高/圆角/边框/阴影偏移）不在间距令牌管辖内，勿扩大化

### C. 测试钉死方案
1. 新增 vitest 静态审计测试（解析 <style> 文本或编译产物 CSSOM）：断言点名链路文件的 margin/padding/gap 声明只准出现 var(--jiange-*) 或白名单值（0、auto、4px 细档令牌），出现裸 px 字面量即红——把 grep 口径固化成回归门
2. 对称性断言：解析 .zhanji-liebiao 规则，断言 paddingTop === paddingBottom（钉死"上下不一致"不复发）
3. 双机制叠加断言：凡容器声明 gap 的，其直接子项选择器不得再声明纵向 margin（静态可查，账号与安全/过往战绩两案即此病）
4. 浏览器端回归交给 FP-I3 截图对比（浅+深、移动视口）

## 6. 结论

- 用户点名问题：**证实**，上 0px / 下 24px，Δ=24px，根因四条硬编码叠加（§2 行号）
- 主代理推断：**部分证实**（硬编码属实；"与令牌混用"不成立——点名链路零令牌；非 margin 塌陷，是 flex gap+margin 逐层叠加）
- 令牌体系：三档不够用，覆盖率仅 13%，需补 4px/2px 细档并决策 12px 归属（§3）
- 抽查 3 页：横向溢出全无、对齐无错位、应用自身控制台 0 error；主页与账号与安全各存在与点名问题同型的间距混杂（§4）
