## 阶段 2：根因深挖（5 问法到根因层 + 最强替代解释 + 区分观察）

- D1 根因：`huiDaoJinRi` 用 `keYiHuiJinRi`（基于 setup 期快照 `jinRi.value` 的 computed）做守卫，
  守卫通过后才 `jinRi.value = jinRiSan()` 刷新。跨午夜场景下旧今天仍在 [min,max] 内则守卫放行，
  刷新出的新今天已越界（如 max=今日），随后 `jiaZhenRuFanWei` 钳位到边界并导航换月 = 越界副作用。
  替代解释“钳位函数本身错”被否定：`jiaZhenRuFanWei` 行为正确，错的是守卫判据过期。
  区分观察：FP01 今天导航守卫用例 2（越界合成事件零副作用）在静态 max 下通过，
  用户复现要求 fakeTimers 跨午夜动态越界——旧守卫在该输入下放行。
  修复：守卫直接判 `shiFouKeXuan(jinRiSan())`（新鲜今日），刷新后钳位只走合法分支。
  注意：模板 `:disabled="!keYiHuiJinRi"` 仍吃旧快照（禁用态显示用），与守卫判据分离是故意的：
  禁用态只管“看起来可点”，真守门由函数内新鲜判据承担，与 FP01 用例 2 的合成事件口径一致。
- D2 根因：`.anniu-zhuyao:hover:not(:disabled)` 特异度 (0,3,0)，
  `.anniu-zhuyao[aria-busy='true']` 特异度 (0,2,0)，悬停时 hover 胜出把 filter 抬到 1.06。
  取消态 `disabled=false`（需保持可点以支持取消），故 `:disabled` 暗化救不了。
  修复：补 `.anniu-zhuyao[aria-busy='true']:hover:not(:disabled)`（特异度 0,3,0 + 文档序在后）
  与 `::before` 同选择器守色，filter 锁 0.82、阴影/位移/扫光压回静置值。
  替代解释“改 disabled 语义”被否定：取消按钮必须可点，disabled=false 是定案要求。
- D3 根因：对象侧 378-382 走 `解析性别` 清洗后才落 `male/female`，自身侧 373-376 直接
  `ziLiaoShuJu.xingBie = moRen` 把原始值（含未知脏写法）写入。`可以下一步` 只判非空，
  脏值即污染向导可下一步，且 `解析主色档` 对脏值回退 nan 造成显示与判定分叉。
  修复：自身侧同样 `解析性别(moRen)`，`nan→male / nv→female`，不可识别不写。
  起始步骤推导 383-384 本就走解析口径，修后预选与推导同源。
- D4 根因：`moRenDuiXiangWenAn` 用 `muBiao === '男'/'女'/'未知'` 三字面全等，
  后端 `mu_biao_xing_bie` 为展示形态但历史库存在 `male/female` 写法（类型仍是展示形态| null，
  实际脏数据存在），此时显示“未设置”而向导侧 `解析性别` 认已设并直达步骤 3 = 两处口径分叉。
  修复：改走 `解析性别` 口径（nan→男文案 / nv→女文案），`'未知'` 字面保留为展示形态真源分支，
  其余不可识别一律未设置。`用户形态` 既有导入保留（1419 行仍用），新增 `解析性别` 具名导入。
- D5 根因：`推导起始步骤` 在测试文件内自带一份实现，生产向导 383-387 的分支漂移时测试仍绿。
  修复：函数先对向导生产分支做四行结构断言（自身行/对象行/双默认行/仅自身行），
  漂移即红；再用解析口径求值。`解析性别` 既有导入保留（仍用于求值）。
