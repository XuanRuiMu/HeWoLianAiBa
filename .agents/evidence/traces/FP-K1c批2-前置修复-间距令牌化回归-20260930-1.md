# FP-K1c批2 前置修复：间距令牌化回归（2026-09-30）

## 背景

主代理在派发 FP-K1c批2 前复跑全量测试，发现 **9 处真实失败**（4 文件）：
`FP04b字段纵向间距.test.ts`（4）、`FPA1输入线标签根因.test.ts`（2）、`登录内容.test.ts`（2）、`FP14出生日期选择器.test.ts`（1）。
与 PROGRESS 记载的"2186 用例全绿"不符——上一批令牌化后断言未完全同步，且存在一处几何耦合被误改。

## 根因（两类）

### 根因一：耦合几何常量被误收成间距档（真实样式缺陷）

- 浮标签上浮后越出字段盒 **5px**（`.fudong-biaoqian` 浮动态 `top: -5px`），
  滚动口 `.biaodan-gundong` 必须给等量 `padding-top: 5px` + `margin-top: -5px` 才能不裁切浮标且不跳动（FP-17b）。
- K1b 机械收编时把 5px 误换成最近间距档 `--jiange-6`（6px），打断耦合。
- **5 不是间距节奏档，是几何常量**（与 `--rili-*` 同类）。

### 根因二：测试求值器不认 calc(var()) + jsdom 简写塌零

- 探针证实：jsdom 对**带 calc(var()) 的 padding 简写**返回 `"0"`；对 longhand calc/var 原样返回字符串。
- Vue 构建（postcss）会把 longhand 合并回简写 ⇒ SFC 内写 longhand 也绕不过。
- 四处 `Number.parseFloat` / `split(/\s+/)` 求值器无法解析令牌算式（FP14 还把 calc 按空格拆断）。

## 修复（零补丁、同根因同收口）

| 文件 | 改动 |
|---|---|
| `styles/variables.css` | 新增几何令牌 `--biaoqian-qin-ru: 5px`（共用 :root） |
| `views/登录内容.vue` | 滚动口/浮标签四处改吃该令牌；`top` 静置态改 `calc(var(--jiange-zhong) + var(--jiange-2))`；输入 padding 改 longhand（保可读性，构建合并不影响源码断言） |
| `__tests__/主题令牌真源.ts` | `求几何算式` 支持负因子（`* -1`），此前静默抛错 |
| `__tests__/FP04b字段纵向间距.test.ts` | 输入盒边改从**源码声明 + 求几何算式**取数；`像素()` 兜 calc/var |
| `__tests__/FPA1输入线标签根因.test.ts` | 同上（新增 `源码盒边`） |
| `__tests__/登录内容.test.ts` | 源码断言从字面 px 改为**令牌算式 + 解析值**双钉 |
| `__tests__/FP14出生日期选择器.test.ts` | `数字声明` 走求几何算式；新增 `拆简写值`（括号感知拆分） |
