## 修正I【中·同族残留洞】整串全等漏掉后代/复合选择器 → 改按**主体选择器(subject)**匹配

- 位置：测试文件 `收集声明对`。
- 机理：修正A 用"按 `,` 切分后整串全等"堵住了 `.zhanji-liebiao-neirong` 污染，但**同时排除了所有非纯类选择器**——而本项目大量使用后代选择器（战绩页内 6 处 `:root[data-theme='light'] .jiazai-zhuangtai` 等）。这些块的**主体选择器就是目标类**，声明真实作用于该元素，但门禁收集不到。
- 修复：新增 `取主体()`（按顶层组合子 `空格/>/+/~` 切分取末段）+ `主体作用于()`：
  1. 主体 === 目标 → 命中；
  2. 主体 = 目标 + 追加成分（`.类`/`:伪类`/`[属性]`）且**不含伪元素** → 命中（如 `.zhanji-liebiao.tuo-zhuai-zhong`、`.zhanji-liebiao:hover`）；
  3. 主体含伪元素（`::before`/`::-webkit-scrollbar-*`）→ 排除（不影响元素自身盒模型）；
  4. 目标只在祖先位置（主体 ≠ 目标，如 `.zhanji-liebiao .zhanji-kapian`）→ 排除；
  5. 异名类天然排除（`.fenlei-kong-zhuangtai` 不以 `.kong-zhuangtai` 开头）。

### 自测（旧=修正A 整串全等 / 新=主体匹配）
| 反例 | 期望 | 旧 | 新 |
|---|---|---|---|
| `:root[data-theme='light'] .kong-zhuangtai { padding-top:8px }` | 应捕获 | 0 条 **漏** | 1 条 **捕获** |
| `.zhanji-liebiao.tuo-zhuai-zhong { padding-top:8px }` | 应捕获 | 0 条 **漏** | 1 条 **捕获** |
| `.zhanji-liebiao::-webkit-scrollbar-track { padding-top:8px }` | 应排除 | 0 条 排除 | 0 条 排除 |
| `.zhanji-liebiao .zhanji-kapian { padding-top:8px }` | 应排除 | 0 条 排除 | 0 条 排除 |
| `.fenlei-kong-zhuangtai { padding-top:8px }` | 应排除 | 0 条 排除 | 0 条 排除 |

**断言级反例**（主题块写 `.kong-zhuangtai { margin-top: 8px }` → 对称断言"下间距"应=16）：
| | 读到 空态卡 margin-top | 下间距 = 4+12+该值 | 判定 |
|---|---|---|---|
| 旧（整串全等） | 0（收集不到主题块） | **16** | **绿（假绿）** |
| 新（主体匹配） | 8px | **24** | **判红** |

## 修正K【低】上下文切分只认 @media → 纳入 @supports/@container/@layer

- 修复：`切上下文` 的头部正则由 `/@media[^{]*\{/` 改为 `/@(?:media|supports|container|layer)[^{]*\{/`，与 @media 同机制。

### 自测（**诚实结论：检测能力无差异，仅上下文归属更正确**）
| 反例 | 旧 | 新 |
|---|---|---|
| `@supports (display: grid) { .zhanji-liebiao { padding-top:8px } }` | 上下文 **1** 个，捕获 **1** | 上下文 **2** 个，捕获 **1** |
| `@container (min-width:400px) { … }` | 上下文 **1** 个，捕获 **1** | 上下文 **2** 个，捕获 **1** |
| `@layer base { … }` | 上下文 **1** 个，捕获 **1** | 上下文 **2** 个，捕获 **1** |

**为何改前也捕获**：`收集声明对` 的规则正则 `([^{}]+)\{([^{}]*)\}` 会扫描任意 at-rule **体内**的最内层规则，即使该 at-rule 未被切为独立上下文（被并入 `base`），其内部规则仍会被扫到。故旧实现的"盲区"并不成立——**检测层面改前改后等价**。
**修正K 的真实价值**：上下文**归属**更正确——条件覆盖不再污染 `base` 口径（`base` 现在只反映无条件规则），条件覆盖被正确归入各自上下文并由 `全并` 悲观口径体现。这是结构性/健壮性改进，非检测增量。已如实登记（见下「能力边界」）。
测试用例「门禁自证·修正K」断言三种 at-rule 均被切为独立上下文且其内 padding-top 覆盖可被读出。

## 修正L【文档】门禁能力边界显式登记

已在测试文件**顶部注释**新增「门禁能力边界（已知抓不到，诚实登记）」一节，并在本文件「能力边界清单」复述：

### 能力边界清单（本门禁抓不到 / 不修）
| # | 抓不到的写法 | 为何不修 / 如何绕过 |
|---|---|---|
| 1 | 间距值藏在组件局部自定义属性：`--foo-gap: 8px; gap: var(--foo-gap);` | 值出现在**非间距属性**（`--foo-gap`）上，门禁只看 margin/padding/gap 族声明，故放行。**不一律禁自定义属性**：项目存在合法几何令牌先例（`--zhanji-yi-dong-zuo-kuan: 74px` 为几何常量非间距档），一律禁会误伤。如需覆盖，应由 FP-K1c 增"间距族自定义属性"专项规则。 |
| 2 | `calc()`/`min()`/`max()`/`clamp()` 内**非 var 数字**：`gap: calc(1rem + 2px)` 判红；但 `gap: calc(100% / 8)`（无长度单位）不判红 | 门禁只认长度单位字面量（px/rem/em/pt/cm/mm/in/pc/q），无单位的相对算式不在管辖内。 |
| 3 | JS/内联样式注入（`el.style.paddingTop = '8px'`）或 `<style>` 之外注入 | 静态源码门禁完全看不到；需运行时/浏览器取证补充。 |
| 4 | 简写与逻辑属性并存的**层叠优先级** | 只按源码顺序近似（`padding` 后跟 `padding-block-start` 视为后者覆盖），未实现完整 CSS 层叠（特异性/来源/层叠层）；对"同文件同选择器顺序书写"的项目惯例足够。 |
| 5 | 主体选择器匹配是**近似**：`:is()/:where()/:has()` 内的目标、`&` 嵌套语法、属性选择器内的类名不展开 | 本项目未使用这些语法；如引入需扩展 `取主体`。 |
| 6 | 覆盖面仅**点名链路三文件** | "滚动容器 padding-top 恒 0"升级为**全站门禁**属 FP-K1c 职责，本文件不做（本轮按要求未扩大范围）。 |
