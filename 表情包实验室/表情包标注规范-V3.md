# 表情包标注规范 V3（人设气质 + 圈层门槛版）

> 版本：2026-11-19 V3（在 V2 基础上新增 2 个字段与梗义考据纪律）
> 适用：存量约 1.9 万张表情包的全量重标注（逐张看图重写）
> 唯一标注语言：简体中文
> 面向执行者：deepseek-v4.1-flash（具备图像理解能力）
> 相比 V2 的变化：新增 `人设气质`、`圈层门槛` 两个必填字段；新增「梗义考据」硬纪律；修正示例（奶龙/鲸鱼娘）。

---

## 〇、为什么 V3 要多这两个字段（一句话背景）

论文证据表明：人发什么表情包 = **情绪 × 功能 × 关系 × 身份人设 × 梗圈层 × 场合** 的联合决策（详见 `表情包实验室/调研-表情包发送决策因素-论文补充调研.md`）。

- V2 只覆盖了「情绪/场景/关系阶段/风格」，漏掉了：**「这个人设配不配发这张图」**（鲸鱼娘问题）和 **「这个梗这张图到底什么意思」**（奶龙问题）。
- V3 用 `人设气质` 解决第一个，用 `圈层门槛` + 梗义考据解决第二个。
- 系统读取时，缺省值与 V2 行为完全兼容（见第八节），不会让旧数据失效。

---

## 一、这份规范要干什么

1. **重写标注**：根据图片真实内容与风格，重写描述、情绪、场景等字段；
2. **重命名**：根据内容与风格更新表情包名字（图片文件名 + 短名）；
3. **剔除垃圾**：图片不属于表情包范畴、或意义不明不知何时该发的，直接删除图片文件。

---

## 二、处理对象与输出格式

### 2.1 输入

- 图片目录：`表情包/`（第一层，约 19,318 张：.jpg 12,585 / .gif 4,414 / .png 1,941 / .webp 378）
- **微信原生小表情（109 个 `wx_*`）不属于表情包**：它们与 emoji 同类，已移出 `表情包/` 目录、进入用户可用的 emoji 表情体系（前端 emoji 面板与文本内联渲染）。本规范不处理它们，遇到 `wx_*` 文件一律跳过（不标注、不重命名、不删除）。
- 同名 `.json` 已存在时，直接覆盖重写。

### 2.2 输出：每张图一个同名 JSON（共 9 个字段）

```json
{
  "短名": "奶龙瞪眼震惊",
  "描述": "奶龙瞪圆眼睛侧头斜睨，配字'惊鸿一瞥'，是玩梗式夸张震惊：'我看到了不得了的东西'，替那句'好家伙/我直接看愣'",
  "情绪标签": "好笑",
  "适用场景": "对方说了很离谱或很惊艳的内容时夸张接梗；自己被震撼到时玩梗回应；关系熟了互相甩梗图时",
  "启用": true,
  "风格": "梗图",
  "关系阶段下限": "认识",
  "人设气质": ["沙雕搞怪", "高冷毒舌"],
  "圈层门槛": "亚文化"
}
```

- 字段全部为中文 key，共 9 个，一个都不能漏。
- 图片主名改成什么（新文件名），JSON 文件主名改成一样的；例：`旧名.png` 重命名为 `奶龙瞪眼震惊.png`，则标注文件为 `奶龙瞪眼震惊.json`。
- **不要输出任何多余的字段**（不要加「歧义度」「来源」「梗龄」之类）。

### 2.3 剔除：直接删除图片文件

判定为「无意义」的图，**直接删除这张图片文件**，就当它不存在，不产出 JSON、不留任何记录、不产生任何额外清单文件。

## 三、九个字段的硬规则

| 字段 | 必填 | 类型 | 上限 | 规则 |
|---|---|---|---|---|
| `短名` | **必填** | 字符串 | ≤30 字符 | 全库唯一；不能含 `[` `]` `【` `】` `:` `：` 和换行；中文/字母/数字/短横线；是 AI 输出 `[贴纸:短名]` 用的名字，必须一眼看懂 |
| `描述` | 必填 | 字符串 | ≤120 字符 | 说清「图上有什么 + 配字是什么 + **梗的正确含义** + 替哪句话」 |
| `情绪标签` | 必填 | 字符串 | ≤30 字符 | 12 选 1（见 3.1） |
| `适用场景` | 必填 | 字符串 | ≤120 字符 | 具体到聊天语境与功能（见 3.4） |
| `启用` | 必填 | 布尔 | — | 一律 `true` |
| `风格` | 必填 | 字符串 | ≤30 字符 | 4 选 1（见 3.2） |
| `关系阶段下限` | 必填 | 字符串 | ≤30 字符 | 10 档选 1（见 3.3） |
| `人设气质` | **必填（V3 新增）** | 字符串数组 | 1–3 项 | 8 选 1–3（见 3.5）；决定「什么性格的人设能发这张」 |
| `圈层门槛` | **必填（V3 新增）** | 字符串 | ≤10 字符 | 3 选 1（见 3.6）；决定「这个梗多小众」 |

### 3.1 情绪标签（12 个，只能选一个）

`好笑`、`感动`、`无语`、`赞同`、`撒娇`、`安慰`、`庆祝`、`破冰`、`告别`、`卖萌`、`生气`、`委屈`

- 只选最主导的一个。判断口诀：**这张图替 AI 说出哪句话**。
- 震惊/震撼类（如奶龙惊鸿一瞥）归 `好笑`（玩梗式夸张）而不是「无语」；只有真正表达「无奈、翻白眼、说不出话」才用 `无语`。

### 3.2 风格（4 个，只能选一个）

| 值 | 含义 | 判定标准 |
|---|---|---|
| `黄脸` | 系统圆脸、笑脸、经典表情 | 微信/QQ 小黄脸、emoji 表情、圆脸卡通脸 |
| `祝福` | 花草风景、早安图、祝福大字图 | 风景/花朵/日出 + 大字祝福 |
| `日常` | 温和的生活化贴图 | 真人/宠物/美食/生活照 + 简短配字，语气温和 |
| `梗图` | 网络梗、自嘲、拼贴、沙雕、斗图类 | 熊猫头、金馆长、暴漫、meme 拼贴、大字喊话、夸张搞怪、IP 二创 |

- 45 岁以上人设只会拿到黄脸/祝福/日常；大字喊话/粗口/暴力梗图一律归 `梗图`。

### 3.3 关系阶段下限（10 档，按序取）

`冷淡`(0) < `疏远`(1) < `认识`(2) < `熟悉`(3) < `朋友`(4) < `好友`(5) < `暧昧`(6) < `心动`(7) < `热恋`(8) < `深爱`(9)

- 默认全部填 `认识`。
- 亲亲/抱抱/爱心/么么哒/暧昧挑逗 → `暧昧`；粗口/性暗示/重口 → `心动`；情侣私密梗 → `热恋`。宁低勿高。

### 3.4 适用场景怎么写（V3 强化）

场景要写「聊天功能 + 时机」，论文实证的真人功能有六类，写作时至少体现一类：
1. **表达情绪**（夸/感动/生气…）
2. **澄清/消除歧义**（怕对方误会时）
3. **活跃气氛/接梗**（玩梗、起哄）
4. **软化语气**（拒绝、提要求时垫一张）
5. **避免尴尬/垫场**（话题接不下去）
6. **结束对话**（没话说了体面收尾）

❌ 反例：「任何场合都能用」「日常聊天」
✅ 正例：「对方说了很离谱的内容时夸张接梗；被震撼到时玩梗回应」

### 3.5 人设气质（8 个枚举，选 1–3 个）★V3 新增★

| 枚举值 | 对应人设画像 | 典型图 |
|---|---|---|
| `可爱萌系` | 软萌、元气、爱撒娇、喜欢小动物、说话软 | 鲸鱼娘、猫猫柴犬、粉嫩贴纸、比心卖萌 |
| `沙雕搞怪` | 爱玩梗、接梗快、自嘲、发疯文学 | 奶龙、熊猫头、金馆长、暴漫、发疯文字图 |
| `高冷毒舌` | 话少、毒舌、阴阳怪气、懒得解释 | 翻白眼、礼貌微笑、刀、告辞、鞋垫 |
| `温柔治愈` | 温柔体贴、会哄人、擅长安慰 | 抱抱、递纸巾、摸头、暖色系贴图 |
| `正经严肃` | 理性、认真、不爱玩梗 | 握手、OK、认真脸、鼓掌、正经敬礼 |
| `文艺清新` | 文艺、安静、喜欢文字和风景 | 风景、句子图、星空、胶片感 |
| `热血燃系` | 打鸡血、运动系、正能量 | 加油、拳头、燃烧、体育梗 |
| `通用` | 任何人设都能发（默认值） | 万金油：微笑、OK、问号、鼓掌 |

规则：
- **数组，1–3 项**。一张图通常 1 个主气质；兼容性强的写 2–3 个。
- 判断口诀：**「这个项目里什么性格的角色发这张不违和？」** 反推：壮汉硬汉发鲸鱼娘卖萌图违和 → 鲸鱼娘不能标 `通用`。
- 与系统人格的映射关系（代码侧会拿角色的人设文本/MBTI 匹配）：
  - `可爱萌系` ↔ 软萌/元气/撒娇/ISFP/ESFP/INFP 类描述
  - `沙雕搞怪` ↔ 沙雕/爱玩梗/ENTP/ESTP/发疯
  - `高冷毒舌` ↔ 高冷/毒舌/INTJ/ISTP/淡漠
  - `温柔治愈` ↔ 温柔/体贴/ISFJ/INFJ/会哄人
  - `正经严肃` ↔ 理性/严谨/ISTJ/ESTJ
  - `文艺清新` ↔ 文艺/安静/INFP/阅读写作
  - `热血燃系` ↔ 热血/运动/正能量/ESTP
- **`通用` 只给真正万金油的图**；只要一张图「换个硬汉人设发就怪」，就不许标 `通用`。

### 3.6 圈层门槛（3 选 1）★V3 新增★

| 枚举值 | 含义 | 判定标准 | 典型图 |
|---|---|---|---|
| `大众` | 不懂梗也能看懂 | 情绪直白：微笑、哭、抱抱、比心、OK | 微笑、OK、爱心 |
| `亚文化` | 需要认识这个 IP/梗才 fully get | 奶龙、鲸鱼娘、Chiikawa、库洛米、 VIRUS 二创、平台专属梗 | 奶龙系列、鲸鱼娘系列 |
| `深度梗` | 需要懂出处/圈内黑话 | 拼贴、缩写梗、连环梗、圈内黑话 | 硬核抽象梗、连环meme |

规则：
- **IP 形象图一律不低于 `亚文化`**（认识这个 IP 才算 get 到）。
- `深度梗` 的图，系统会要求关系阶段 ≥ `熟悉` 才给候选（代码侧联动）。
- 拿不准时往低了填（填 `大众` 最坏只是早解锁，不会出错）。

## 四、短名与重命名规则

### 4.1 短名怎么起

1. 中文短语，≤30 字符（建议 3–8 字），结构「主体+动作/情绪」：`熊猫头摊手`、`猫猫流泪`。
2. 图上有经典配字的要体现：`雨女无瓜`、`退退退`、`栓Q`。
3. 同系列前缀一致：`奶龙瞪眼震惊`、`奶龙大笑`。
4. 禁止：纯数字/标点/`无意义`/`表情`/`未命名`，以及与图意不符的名字。

### 4.2 文件名怎么改

- 文件名 = 短名 + 原扩展名；改名后 JSON 主名同步；**短名 == 文件主名**。
- 撞名加序号：`熊猫头摊手2`。
- 不用改名的情形：
  - 旧名已是干净贴切的中文短名（≤15 字、无乱码、无站点残留）。
- `wx_*` 文件不在本目录，不适用本节。

### 4.3 什么名字必须改

1. 无意义编号：`IMG_1234`、`mmexport123`、`未命名`；
2. 下载站残留：`【高清】xxx-第3弹-某某网.jpg`；
3. 与图意不符；
4. >15 字符或带乱码。

## 五、剔除规则（命中任一条 → 直接删除图片文件）

1. **非表情包范畴**：普通照片/风景照/证件照/截图/海报/合辑拼图；纯文字大字报（无角色无画面）；纯 logo/广告/二维码。
2. **意义不明，不知道什么时候该发**：画面无法判断表达什么；无可读配字且画面抽象混乱；文字糊成一团无法辨认图意。
3. **低质量不可用**：严重模糊/大面积马赛克/全黑全白/裁切得看不出主体；文件损坏。
4. **违规内容**：色情、裸露、性行为；血腥、暴力伤害、虐待、尸体；其他明显不宜出现在恋爱聊天场景的内容。

**注意**：粗口/沙雕/阴阳怪气但属正常网络梗文化的图（熊猫头骂人、金馆长阴阳怪气）**不算违规，保留**。

## 六、执行要求

1. **逐张看图**：必须对每张图实际用视觉能力理解，禁止只读文件名或旧 JSON 猜内容。
2. **梗义考据（V3 硬纪律）**：凡是 IP 形象图/网络梗图（奶龙、鲸鱼娘、Chiikawa、库洛米、林妙妙、熊猫头模板变体等），**必须先确认这个梗/IP 的来源与主流用法，再下笔写描述**；描述要写「梗的正确含义」，禁止按画面动作望文生义。拿不准的梗 → 按「意义不明」剔除（宁缺毋滥）。
3. **每张图一个结果**：要么产出一条 9 字段 JSON，要么直接删除图片文件。
4. **描述和场景必须具体**，体现 3.4 的六类功能之一，禁止空话。
5. **情绪标签分布要真实**：好笑/赞同/卖萌/安慰/破冰 占大头，无语/生气/委屈/告别 是少数（无语占比 ≤15%）。
6. **人设气质不许偷懒全标 `通用`**：全库 `通用` 占比应 ≤40%；IP 形象图必须标出具体气质。
7. **短名全库唯一**；只改名不改图（不裁剪、不转码、不覆盖图片内容）。
8. **进度与日志**：每处理 200 张输出一次进度：已处理 X / 共 19318，产出 JSON A 条、改名 B 条、删除 C 条。

## 八、与系统代码的衔接（给后续开发，标注 AI 不用管）

- JSON 新增字段后，后端 `表情包库.ts` 解析时：`人设气质` 缺省 → 视为 `["通用"]`；`圈层门槛` 缺省 → 视为 `大众`。**旧 JSON 不改也能按 V2 行为运行**。
- 候选过滤链在现有「风格白名单 + 关系阶段下限」基础上追加两道闸：
  1. **人设气质闸**：角色人设文本（性格/言语风格/行为特点/MBTI）命中的气质集合，与候选图的 `人设气质` 有交集才入选；`通用` 图始终放行。
  2. **圈层门槛闸**：`亚文化` 图要求关系阶段 ≥ `认识` 且人设不是 `正经严肃` 独占型；`深度梗` 图要求关系阶段 ≥ `熟悉`。
- 这两道闸只影响「候选池」，不改变「发不发由门控决定」的现有架构。
