# 分析-真实微信表情行为

> 数据来源：`语料实验室2/wechat_record.csv`（主文件，下称 A）与 `语料实验室2/wechat_record_test_utf8.csv`（大样本文件，下称 B）。
> 分析日期：2026-11-18。所有数字均来自对两个 CSV 的 Python 脚本实算，无编造。

## 0. 数据口径

| 项 | 说明 |
| --- | --- |
| A 文件 | 2180 条，2023-11-29 ~ 2024-02-22，57 个活跃日，TalkerId 两个（3: 2068 条，11: 112 条），有完整 Type 字段 |
| B 文件 | 13706 条，2023-01-01 ~ 2024-01-31，313 个活跃日，无 Type/TalkerId 列，仅 IsSender/StrContent/StrTime |
| 表情判定 | A：Type=47；B：无 Type 列，按 StrContent 以 `<msg>` 开头且含 `<emoji` 判定（与 A 文件 Type=47 完全一致，已验证 205/205 吻合） |
| emoji type 属性 | XML 内 `type="1"`=微信小黄脸，`type="2"`=自定义/动画表情，`type="3"`=其他（疑似系统表情） |
| 文本内 `[xx]` | 是文字消息里渲染的内置 emoji 标签，不是 Type=47；单独统计 |
| 排除 | 非表情 XML（图片/语音/视频/撤回等）不计入表情，但计入消息总数 |
| 会话切分 | 相邻消息间隔 > 30 分钟视为新会话 |
| 时间 | 全部按 StrTime/CreateTime 的本地时间处理 |

B 文件是同一对机主更长时间的主聊天记录（A 是其末段子集，按时间+内容比对吻合），以下两文件结果并列展示，机器人和结论以样本量更大的 B 为主、A 交叉验证。

## 1. 表情消息占比

| 口径 | A | B |
| --- | --- | --- |
| 总消息 | 2180 | 13706 |
| 表情(Type=47) | 205 | 1711 |
| **表情占比** | **9.40%** | **12.48%** |
| 机主(IsSender=1)消息 | 1369 | 8155 |
| 机主表情 | 180（13.15%） | 1555（19.07%） |
| 对方(IsSender=0)消息 | 811 | 5551 |
| 对方表情 | 25（3.08%） | 156（2.81%） |

结论：机主发表情频率是对方的 4~7 倍；在亲密聊天里，机主约每 5~7 条消息就有 1 条是表情包。

## 2. 时间分布（按小时，本地时间）

表情占比按小时（表情数/该小时消息数）：

- B 文件：白天 08:00-22:59 共 13463 条消息、1684 条表情（12.51%）；夜间 23:00-07:59 共 243 条、27 条（11.11%）。深夜消息少但表情率并不低（0 点 13.3%、4 点 14.3%），没有"深夜更爱发表情"的显著信号，表情率全天稳定在 10%~18% 区间。
- A 文件：白天 9.50% vs 夜间 4.65%，深夜样本太少（43 条）不具统计力。
- 绝对数量高峰在聊天高峰时段：B 文件表情数 top 小时为 12 点(280)、17 点(173)、18 点(148)、9 点(134)、16 点(126)，即午休和下班前后是发表情最多的窗口。

## 3. 表情与上下文（前一条消息类型）

统计口径：对每条表情消息取其前一条消息，用关键词启发式分类；同时给出所有消息（含非表情）在同一前文类别下的表情率，即 P(本条是表情 | 前一条类别)。

B 文件（1711 条表情）：

| 前一条类别 | 表情/总数 | 表情率 |
| --- | --- | --- |
| 问候/作息（晚安/早/睡） | 61/262 | 23.28% |
| 亲昵/调情（想/爱/抱/亲/么么） | 46/246 | 18.70% |
| 日常汇报（吃/饭/下班/上班/到家） | 131/727 | 18.02% |
| 感叹(!/！) | 5/28 | 17.86% |
| 负面情绪（累/哭/烦/委屈） | 8/46 | 17.39% |
| 短句(≤14字) | 930/6809 | 13.66% |
| 长句(≥15字) | 55/445 | 12.36% |
| 答应/附和（好/嗯/行/可以） | 109/1074 | 10.15% |
| 前一条是表情 | 160/1711 | 9.35% |
| 提问(？/? ) | 88/966 | 9.11% |
| 图片/语音/撤回等 XML | 114/1349 | 8.45% |
| 道歉 | 2/26 | 7.69% |
| 笑（哈哈/笑死） | 1/16 | 6.25% |

A 文件交叉验证：亲昵 23.08%、问候作息 14.89%、长句 14.89% 为 top3，方向一致（A 中"笑/玩笑"仅 6 条样本，比率不稳定）。

真实样例（B）：「吃饺子没呀」→表情；「睡觉觉」→表情；「么么哒[飞吻]」→表情；「今晚9点去花街？」→表情。

另：表情前一条是同侧（机主自己）820 次、对侧 890 次，接近 1:1——表情一半是"接对方话"，一半是自己接着补一张。

## 4. 斗图/连续表情行为

| 指标 | A | B |
| --- | --- | --- |
| 对方发表情次数 | 25 | 156 |
| 机主 2 分钟内也回表情 | 1（4.00%） | 27（17.31%） |
| 机主 2 分钟内回任意消息 | — | 126/156（80.8%） |
| 连续表情 run 段数 | 182 | 1551 |
| run≥2 的段占比 | 9.34%（17/182） | 8.45%（131/1551） |
| 连发(≥2)表情占全部表情条数 | 19.51% | 17.01% |
| run 长度分布 | 1:165, 2:13, 3:2, 4:2 | 1:1420, 2:107, 3:20, 4:3, 5:1 |
| 机主跟自己上一条表情连发 | 16 | 84 |

解读：真人很少真正"斗图对轰"——对方发表情后机主回敬表情的概率只有 4%~17%，更常见的是回文字（B 中 80.8% 会回话，其中多数是文字）。但"自己连发 2~3 张"的行为占表情总量的 17%~20%，是稳定习惯。

## 5. 表情 vs 文字：单独成条还是混排

- Type=47 表情 100% 单独成条（A 205/205、B 1711/1711，条内无文字）。
- 文字消息里带 `[xx]` 内置 emoji 标签：A 246 条（占非表情消息 12.46%）、B 1544 条（12.87%）。
- 纯 `[xx]` 组成的"文字表情"（如 `[猪头]`、`[旺柴]` 单独成条）：A 73 条（3.83%）、B 475 条（3.84%）——稳定约 4% 的消息是"文字版表情"。
- 混合形态「选一个[旺柴]」「这[旺柴]」很常见：即"短文字+一个语气 emoji"是一种固定句式。
- 30 秒内"先发一条文字、紧跟着补一张表情"的组合：A 71 次、B 514 次（约占表情的 30%），这是真人最重要的"文字+表情包连招"。

## 8. 对 AI 表情包机制的启示

1. **表情发送要有明确节奏上限**：真人整体表情占比 9%~12%，机主本人 13%~19%，且小时占比极少超过 18%。AI 每 5~8 条消息发 1 张表情、单小时表情占比不超过 20%，才像真人；逢句必表情会立刻穿帮。
2. **自定义动画表情为主、小黄脸为辅**：真人 78% 的 Type=47 是自定义表情（type2），小黄脸更多以文字 `[旺柴][捂脸]` 形式出现。AI 表情包库应配置一个"常用自定义表情池"（头部 20 个 md5 覆盖约 27% 使用量），文字侧准备内置 emoji 标签渲染。
3. **触发语境优先级**：问候/作息（晚安、早安、睡了）、亲昵调情（想、爱、么么）、日常汇报（吃饭、下班、到家）是表情率最高的三类前文（18%~23%）；而"哈哈"类玩笑反而是低触发语境（6%）。机器人应在"软性、情绪性、生活化"话轮后发表情，而不是在玩梗时发。
4. **文字+表情连招是标志性习惯**：30 秒内"先发短文字，再补一张表情"占表情的约 30%，例如「选一个[旺柴]」+表情。机器人应实现"同轮先回文字、隔 1~3 秒再发表情"的两段式输出，而不是只发一张图。
5. **回敬表情要克制**：对方发表情后，真人 80% 概率回文字、只有 4%~17% 概率回敬表情；连续斗图(run≥2)只占表情量的 17%~20%，且 2 张封顶居多。机器人收到表情时应以文字回应为主，表情回敬是低概率加分项。
6. **表情即开场白**：约 8% 的会话（B：121/1539）第一句就是表情包，短会话表情率反而更高。机器人可在"用户隔夜/隔久后回来"时用表情开场，模拟这种打卡式问候。
7. **亲密度驱动密度**：同一对象在关系热度高时表情率 15%+，降温期跌到 5%~7%。机器人应把表情频率与"当前关系阶段/好感度"挂钩，做成随剧情衰减/增强的动态概率，而不是全局常量。
8. **时间规律照抄真人**：表情绝对数量跟着聊天量走（午休 12 点、傍晚 17-18 点是高峰），深夜总量少但表情率不掉。机器人不需要给深夜特殊加权，按消息节奏自然发即可；同时避免在用户无消息的长间隔里主动刷表情（真人表情 95% 出现在活跃会话内）。
