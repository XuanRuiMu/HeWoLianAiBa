## 二、每张图的处理步骤

对每张图，依次做：

1. **打开图片，用视觉能力看清内容**：主体是什么（人/动物/黄脸/文字/场景）、有没有配字、动作表情是什么。
2. **梗义考据（重要）**：如果这是 IP 形象图或网络梗图（如奶龙、鲸鱼娘、Chiikawa、库洛米、熊猫头模板等），先确认这个梗/IP 的来源与主流用法，再下笔。禁止只按画面动作望文生义（例：奶龙「惊鸿一瞥」的正确含义是「夸张震惊/好家伙」，不是「高冷瞥一眼」）。拿不准的梗 → 按「意义不明」直接删除图片，继续下一张。
3. **判断类型**：正常表情包 → 进入第 4 步；命中《规范》第五节任一剔除条件（非表情包范畴 / 意义不明不知何时发 / 严重糊坏 / 色情血腥违规）→ **直接删除该图片文件**，跳到下一张；粗口/沙雕/阴阳怪气但属于正常网络梗文化 → 不算违规，保留。
4. **重写 9 字段**（全部中文，一个不能漏）：
   - `短名`：≤30 字符、全库唯一、无 `[]【】::`、中文短句，结构「主体+动作/情绪」；图上有经典配字要体现（如「雨女无瓜」「退退退」）
   - `描述`：≤120 字符，写清「图上有什么 + 配字是什么 + 梗的正确含义 + 替哪句话」
   - `情绪标签`：12 选 1 —— 好笑 / 感动 / 无语 / 赞同 / 撒娇 / 安慰 / 庆祝 / 破冰 / 告别 / 卖萌 / 生气 / 委屈（口诀：这张图替 AI 说哪句话；震惊类玩梗归「好笑」）
   - `适用场景`：≤120 字符，聊天语境 + 六类功能之一（表达情绪 / 澄清消除歧义 / 活跃气氛接梗 / 软化语气 / 避免尴尬垫场 / 结束对话），禁止「任何场合」式空话
   - `启用`：一律 `true`
   - `风格`：4 选 1 —— 黄脸 / 祝福 / 日常 / 梗图
   - `关系阶段下限`：默认 `认识`；亲亲/爱心/暧昧挑逗→`暧昧`；粗口/性暗示/重口→`心动`；情侣私密梗→`热恋`（宁低勿高）
   - `人设气质`：8 选 1–3 —— 通用 / 可爱萌系 / 沙雕搞怪 / 高冷毒舌 / 温柔治愈 / 正经严肃 / 文艺清新 / 热血燃系。判断口诀：「这个项目里什么性格的角色发这张不违和？」——壮汉硬汉发鲸鱼娘卖萌图违和，所以鲸鱼娘只能标「可爱萌系」；`通用` 只给真正万金油的图（微笑/OK/问号/鼓掌），IP 图禁止标通用
   - `圈层门槛`：3 选 1 —— 大众（不懂梗也能看懂：微笑/哭/比心/OK）/ 亚文化（需要认识这个 IP：奶龙、鲸鱼娘、Chiikawa 等所有 IP 形象图）/ 深度梗（圈内黑话、连环梗、缩写梗）。拿不准往低了填
5. **决定文件名**：`wx_` 开头的 109 个原生表情 → 文件名不动；旧名本来就是干净贴切的中文短名（≤15 字、无乱码、无站点残留）→ 文件名不动；文件名是编号/乱码/下载站残留/与图意不符/超长 → 直接改成「短名 + 原扩展名」，短名撞名时加序号（`熊猫头摊手2`）。
6. **写输出**：把 JSON 写到 `表情包/<短名或原主名>.json`（UTF-8），改名则同时重命名图片文件。
7. 每处理 200 张，输出一次进度：已处理 X / 共 19318，其中产出 JSON A 条、改名 B 条、删除 C 条。

## 三、质量红线（违反则本条作废重做）

1. **必须逐张实际看图**，禁止只读文件名或旧 JSON 猜内容。
2. **梗图必须先考据梗义再写描述**，描述里要体现梗的正确含义；拿不准的梗直接删图，宁缺毋滥。
3. **禁止情绪标签偷懒全标一个**。旧库 1.4 万/1.9 万条全标「无语」是反面教材；好笑/赞同/卖萌/安慰/破冰 应占大头，无语占比控制在 15% 以下。
4. **禁止人设气质偷懒全标「通用」**：全库「通用」占比 ≤40%；所有 IP 形象图必须标具体气质（如鲸鱼娘→可爱萌系、奶龙→沙雕搞怪）。
5. **描述和场景必须具体**，场景要落在六类功能之一，禁止「微信原生表情：xx」式套话。
6. **短名全库唯一**，撞名按规则加序号；禁含 `[ ] 【 】 : ：` 和换行。
7. **只改名不改图**：不允许裁剪、转码、覆盖图片内容。
8. 剔除就是删除文件本身；不要生成任何额外的清单、日志、备份文件。
