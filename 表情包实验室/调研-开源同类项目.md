# 开源同类项目调研：AI 角色自动发送表情包 / 贴纸的机制

- 调研日期：2026-11-18
- 调研范围：2026-01-01 以来仍在活跃维护的开源项目（GitHub），重点看"AI 角色自动发表情包/贴纸/斗图"的具体实现机制
- 参考对象（甲方现有机制，下称"现有系统"）：
  Director 模型先输出"表情意图"标签（好笑/感动/无语/赞同/撒娇/安慰/庆祝/破冰/告别/卖萌/生气/委屈）→ 按意图 + 关系阶段 + 人格系数 + 回合间隔做门控 → 从约 1.9 万张带 JSON 标注（短名/描述/情绪标签/适用场景/风格/关系阶段下限）的本地表情包库随机抽 8 张作为候选 → 注入 Writer 的 prompt，由 Writer 用 `[贴纸:短名]` 标记决定发不发、发哪张、放在消息什么位置。每轮最多 1 张，深夜/危机/关系初期禁止。

### 2. astrbot_plugin_meme_manager（anka-afk）—— AstrBot 生态最成熟的表情包插件
- 仓库：https://github.com/anka-afk/astrbot_plugin_meme_manager
- 活跃度：**已验证 2026 年活跃**。最新提交 2026-11-18T03:42:14Z（作者 ReedSein 分支）；主仓最近 push 2026-11-18；星标 566；README 徽章要求 AstrBot ≥ 4.28.2、Python ≥ 3.12，当前版本 v5.4.1。
  （来源：https://api.github.com/repos/anka-afk/astrbot_plugin_meme_manager 、https://raw.githubusercontent.com/anka-afk/astrbot_plugin_meme_manager/main/README.md）
- 机制（README 全文可读，细节最全）：
  - **标签粒度 × 选择者 四象限**：分类级（随机取图）× 主模型/额外辅助模型；图片级（语义检索）× 主模型/额外辅助模型。即"LLM 直接选分类"和"LLM 走语义检索选图"都支持。
  - **主动发送工具**：模型可调用 `send_meme`（按分类或按搜索结果发图），**不受自动配图概率与数量上限限制**；开启"仅通过工具发送表情"后只走工具。
  - **语义检索**：`search_memes`（生成检索词查向量索引，返回候选）+ `preview_memes`（支持图片输入的模型先看分类原图再按编号发，每页默认 9 张）。FAISS 语义索引；有索引时用图片描述 + 检索向量按语境选图。
  - **发送概率**：`表情发送概率` 只控制自动配图；0% = 不自动附图，100% 也不保证每轮发。无候选/主动弃选/运行失败时**不补发**。
  - **已知图片 ID 直接引用**：主模型可直接引用当前会话绑定包里的短 ID 跳过检索。
  - **使用规则**：默认/会话/人格三级规则绑定不同表情包，支持多包混用（按顺序匹配，未匹配用默认），无需改人格提示词。
  - **自动收集**：视觉模型识别群聊图片 → 去重 → 分类 → 默认人工审核入包（待审核表情页），审核后可自动生成向量。
  - 其他：WebUI 拖拽管理、兰空/R2/WebDAV/StarDots 图床同步、资源广场安装社区表情包、流式回复中标签在发送前解析（歧义片段先缓冲）。
- 要点：**这是"LLM 自选 + 语义检索 + 工具调用 + 概率闸门 + 审核收集"结合得最完整的开源实现**，且明确支持"不补发"这种反刷屏设计。

### 3. astrbot_plugin_sticker_kit（SucRoseZT）—— "AI 自己写标签配图"的快通道设计
- 仓库：https://github.com/SucRoseZT/astrbot_plugin_sticker_kit
- 活跃度：**已验证 2026 年活跃**。最新提交 2026-11-13T22:52:04Z（release v1.12.0）；星标 4。
  （来源：https://api.github.com/repos/SucRoseZT/astrbot_plugin_sticker_kit/commits?per_page=1 ）
- 机制（README 全文可读，工程细节极丰富）：
  - **两条配图通道**：
    1. **快速通道（省 token）**：AI 在回复末尾直接输出 ` [emotion] /  {"query":"..."} ` 之类的短标签，插件在本地检索配图，**一次回复就带图，无工具调用、无返回记录进历史**。协议本体每轮约 207 token 固定成本，可配库存概览（约 88 token）让 AI 不用检索就知道库里有啥。
    2. **AI 工具调用**：`sticker_pick` / `sticker_search` / `sticker_list`，结果会永久留在对话历史里（每轮重新计费），所以按档位裁剪（`search_detail` 精简/标准/完整、`top_k`、`list_page_size`），实测 665→318 token。
  - **LLM 视觉自动打标**：接入任意 OpenAI 兼容视觉 API，情绪用**受控词表**（一个主情绪 + 至多一个次情绪 + 置信度，杜绝乱标）；v1.12.0 起加独立的 `scene` 用途/动作维度（收到、比爱心、拥抱、敬礼…）参与检索打分；手改字段不会被重打标覆盖。
  - **检索计分（自研，非向量）**：字段加权、主情绪权重 3.0、名称 0.5；每字段只取最佳命中不叠加；低于门槛（`min_score`）或第一名领先不足（`min_margin`）就**只发文字不硬塞**；同分随机；正向最大匹配切词处理无空格长串（蓝发女仆眨眼）；多关键词覆盖加成；危险标签拦截（`blocked_tags`：威胁/血腥/恐怖/暴力/持刀/自杀命中的图不自动发）。
  - **频率四层叠加**：档位（提示词软引导：关闭/很少/适中/较多/每条都发）→ 概率（`send_probability`，默认 0.9，每十次吞一次）→ 冷却（`send_cooldown_seconds`，默认 30s）→ 点名豁免（用户说"表情包/斗图"等关键词直接跳过概率与冷却）。
  - **偷表情包**：别人发表情时 AI 问要不要收进库（或主动偷 `steal_proactive`），默认进待审核；按天折叠管理；冷却 + 每日上限防刷屏。
  - 多模型降级链（主模型限流自动换备用）、打标队列、批量导入限流等工程细节。
- 要点：**与甲方现有系统最像的"意图/情绪标签 → 本地检索 → AI 决定"路线**，但用自研加权检索替代 8 张候选注入，用四层频率闸门替代深夜/危机门控。

### 4. astrbot_plugin_smart_imagechat_hub（QingchenWait）—— 智能斗图 / 主动表情 / 群聊团战
- 仓库：https://github.com/QingchenWait/astrbot_plugin_smart_imagechat_hub
- 活跃度：**已验证 2026 年活跃**。最新提交 2026-07-06T19:54:34Z（"主动发图时减少 token 用量策略"，PR #3）；星标 35。
  （来源：https://api.github.com/repos/QingchenWait/astrbot_plugin_smart_imagechat_hub/commits?per_page=1 ）
- 机制（README 全文可读）：
  - **自动图像特征标注**：上传/偷图后调 LLM（图片转述模型）生成多维标签：图像类别（照片/表情包）、人物特征、身材、情绪、动作、图片中的文本；支持自定义标签类别。
  - **三种检索模式**（省 token 的三档）：
    1. `bot_reply_serial`：先生成 bot 回复，再依据回复内容串行检索表情包（语境最准，慢）；
    2. `user_message_parallel`：依据用户发言并发检索（快，主 LLM 回复前就启动后台检索）；
    3. `user_message_fast_prefilter`：本地精排小规模并发检索（最快），先按标签库强语义命中精排候选，主回复完成时检索没结束就取消任务，仅高置信命中时用本地兜底候选，否则跳过发图。
  - **主动发送表情包**：先按 `主动回复表情包概率`（默认 0.4）命中才启动语义情感分析流程。
  - **群聊斗图**：加入队形（多人连发同图时跟着接龙）、图片连发（概率连发 2 张）、参与团战（连续图片达到 6 张时抽 2 张快速语义分析，从自己图库检索相似图参战）。
  - **最低匹配置信度** 0.45：LLM 输出 confidence 低于该值视为未找到。
  - 表情包嵌入对话中发送 / 独立分段发送可切；非 GIF 转 1 帧 GIF 模拟真实表情包观感；4 种图库导入（插件间迁移、图床同步、群聊偷图、手动传图）。
  - 配套 meme_bridge：把本插件的图像标签桥接给 meme_manager，主动表情零 token 消耗。
- 要点：**多模态语义分析 + 三档延迟策略 + 概率闸门 + 置信度阈值**，工程上对"检索太慢"问题给出了业界少见的并发/取消方案。

### 11. SillyTavern 的 Expression Images（酒馆表情立绘系统）
- 仓库：https://github.com/SillyTavern/SillyTavern ；文档：https://github.com/zhouyi2/SillyTavern-Docs/blob/main/extensions/Expression-Images.md
- 活跃度：**已验证 2026 年活跃**。最新提交 2026-09-14T19:01:34Z（commit 06bde93，Wolfsblvt）。
  （来源：https://api.github.com/repos/SillyTavern/SillyTavern/commits?per_page=1 ）
- 机制（官方文档全文可读）：
  - 角色立绘（sprites）显示在聊天窗口旁/后，按 AI **最近一条回复文本**的情感分类自动切换。
  - **三种分类源**：
    1. **Local**：本机跑一个小情感分类模型（Cohee/distilbert-base-uncased-go-emotions-onnx，默认 **28 个情绪标签**；可换 6 标签的 bert-base-uncased-emotion-onnx），一次只取最可能的 1 个情绪；
    2. **Extras**：Extras 服务的 classify 模块（6 标签默认，可换 28 标签 joeddav/distilbert-base-uncased-go-emotions-student）；

## 二、共同点与差异点

### 共同点（几乎所有项目都做的事）

1. **LLM 输出与图片发送解耦**：没有一家让 LLM 直接输出图片二进制；全部是 LLM 输出**标签/检索词/工具调用/短标记**，框架侧解析后从本地图库取图发送。（ELma `[表情:xx]`、sticker_kit 末尾标签、meme_manager 工具、StickerSelector 意图描述、ST 情绪分类）
2. **本地图库 + 元数据标注**：所有项目都维护本地图库，标注维度大同小异——情绪/情感标签是标配，部分加场景、动作、文本内容、图像类别。
3. **概率/频率闸门是标配**：meme_manager 的发送概率、sticker_kit 的四层频率（档位/概率/冷却/点名豁免）、smart_imagechat_hub 的 0.4 概率、meme_stealing 的 5% 采样、ELma 的概率阈值、Diana 的 30% 复读概率——**"不是每轮都发"是行业共识**，且都允许"点名豁免"（用户明确要就发）。
4. **反刷屏机制趋同**：冷却时间（sticker_kit 30s、ELma 阈值）、每轮上限（meme_manager 数量上限、甲方每轮 1 张）、同图不连发（dsh-qqbot）、不补发（meme_manager）。
5. **图库自增长（偷图/收集）**：MaiBot、smart_imagechat_hub、meme_manager、meme_stealing、sticker_kit、dsh-qqbot 都做"从群聊自动收集表情包 → LLM 打标 → 审核/去重 → 入库"，认为这是让表情系统"像真人"的关键。
6. **审核与去重是标配**：SHA-256 / MD5 去重、待审核池、危险内容过滤（sticker_kit 的 blocked_tags、meme_stealing 的待审核）。

### 差异点（三条主要路线）

| 路线 | 代表 | 核心逻辑 | 优点 | 短板 |
|---|---|---|---|---|
| **A. 标签直出派** | ELma、MaiBot（情绪匹配）、SillyTavern Expression | LLM 回复里打 `[表情:xx]` / 文本情绪分类 → 映射本地图库随机抽 | 实现简单、token 便宜、链路短 | 标签粒度粗、不看语境细节、随机抽容易不贴 |
| **B. 检索增强派** | meme_manager（语义检索）、StickerSelector、smart_imagechat_hub | LLM 生成检索词/意图描述 → 向量或关键词检索图库 → top-k 候选由 LLM 或框架选 | 语境贴合度高、图库大时也能选准 | 依赖 embedding 模型/额外 LLM 调用，token 与延迟成本高 |
| **C. 候选注入派（与甲方相同）** | sticker_kit（快速通道）、meme_manager（主模型自选分类） | 框架先给 LLM 看候选清单（或库存概览），LLM 输出标记决定发哪张/发不发 | 决策质量高（LLM 同时掌握语境与候选）、可表达"都不合适就不发" | 候选注入占 token；候选质量取决于召回 |

实际项目几乎都是混合：meme_manager = B + C + 概率闸门；sticker_kit = C（快速通道）+ B（搜索工具）+ 自研加权检索；smart_imagechat_hub = B + 概率闸门 + 三档延迟策略。

## 三、对现有系统（意图标签→门控→候选注入→Writer 自选）的评价

### 3.1 可以借鉴的做法

1. **候选数量与"弃选"语义要写死**（借鉴 meme_manager"无候选、主动弃选或运行失败时不补发"）：甲方已有"每轮最多 1 张"，建议再显式规定"Writer 全部弃选时不回退随机发"，避免门控被架空。
2. **多层频率闸门比单一门控更稳**（借鉴 sticker_kit 四层：档位→概率→冷却→点名豁免）：甲方的"意图 + 关系阶段 + 人格系数 + 回合间隔 + 深夜/危机/关系初期禁止"已经是多层，但可以再补一个**同图/同系列冷却**（"这周发过的短名不进候选"），防止 Writer 反复挑同一张安全牌。dsh-qqbot 的"同图不连发"与 meme_manager 的"同一回复内短 ID 去重"都是这个思路。
3. **检索质量兜底**（借鉴 sticker_kit 的 min_score / min_margin + 同分随机）：甲方随机抽 8 张时，可先按"情绪标签 × 意图 + 关系阶段下限"过滤再随机，确保 8 张里没有明显违和的；同分时随机已天然满足，但"领先不足就不发"的阈值思想可以移植为"8 张里匹配意图的少于 N 张就降级为不发"。
4. **打标维度可扩展 scene/动作词**（借鉴 sticker_kit v1.12.0 的 `scene` 维度）：甲方 JSON 标注已有"适用场景"，可再补"动作/用途"维度（比爱心、拥抱、敬礼），让候选更贴语境。
5. **偷图/自增长 + 审核池**（借鉴 MaiBot / meme_manager / sticker_kit）：1.9 万张的库运营久了必然过时，增加"从聊天里收集 → 打标 → 审核入库"的通道能持续保鲜，且审核池能防投毒。
6. **检索延迟三档**（借鉴 smart_imagechat_hub）：如果将来把"随机抽 8 张"改成"向量检索 8 张"，直接抄它的 serial/parallel/fast_prefilter 三档，避免拖慢主回复。
7. **协议 token 预算意识**（借鉴 sticker_kit 的实测数据）：候选注入是每轮固定成本，8 张候选每张的 JSON 标注要裁剪（只给短名 + 情绪标签 + 一句描述，不给全字段），并定期用 `/sticker status` 式的诊断命令检查"是 Writer 没写标签还是门控没放行"。

### 3.2 甲方有而别人没有的（相对优势）

1. **独立的 Director 意图模型**：调研到的项目里，意图判断要么内嵌在 Writer 的回复里（ELma 标签、sticker_kit 末尾标签），要么由主模型顺手做检索词（meme_manager）；**把"发不发/发什么情绪"拆成前置小模型（Director）再交给 Writer 自选，这个两段式编排在开源界没有找到同款**。它的好处是 Writer 的上下文不被表情决策污染，且意图标签可复用给其他系统（动作、语音）。
2. **关系阶段 × 人格系数 × 回合间隔的三维门控**：开源项目普遍只有"概率 + 冷却"两维；把关系阶段下限写进表情包 JSON 标注（每张图自带关系门槛）、再叠加人格系数，是比所有调研对象都细的门控。**dsh-qqbot 的好感度只影响"愿不愿意主动开口"，不影响发什么图；甲方把关系深度直接编码进候选过滤，更硬。**
3. **12 个高度定制的意图标签**（好笑/感动/无语/赞同/撒娇/安慰/庆祝/破冰/告别/卖萌/生气/委屈）：比 ST 的 28 情绪词表更贴近"恋爱对话行为"而不是"文本情感分类"；ELma 只有个位数情绪；MaiBot 未公开词表。**这是领域定制优势。**
4. **Writer 对"位置"的控制**：让 Writer 决定贴纸插在消息哪个位置，调研项目中只有 dsh-qqbot 的"图组按顺序渲染"和 meme_manager 的"嵌入 vs 独立"沾边，**没有一家做"同一条消息内插入位置"的语义控制**。
5. **1.9 万张带 JSON 全字段标注的库**：规模与标注完整度超过调研到的所有开源图库方案（sticker_kit 44 张实测、meme_manager 资源广场包、ELma emoji 文件夹手动映射）。

### 3.3 短板（别人有而甲方缺的）

1. **没有语义检索兜底**：当 12 个意图标签都无法覆盖语境时（比如用户说了句方言梗），甲方的候选池只会按意图随机；meme_manager / StickerSelector / smart_imagechat_hub 都能用向量检索从 1.9 万张里直接捞语境最贴的。**建议：给 Writer 的候选注入之外，保留一条"检索通道"作为意图标签的补充**（意图标签命中为空或 Writer 弃选时启用）。
2. **没有自动收集/图库保鲜机制**：所有活跃项目都在做偷图 + 打标 + 审核；甲方 1.9 万张静态库没有自增长通道，长期会过时。
3. **没有"图片内容理解"闭环**：smart_imagechat_hub / meme_stealing / sticker_kit 都用视觉 LLM 给图打标（含图中文字、动作、场景）；甲方 JSON 标注是静态的，无法自动给新图补标注。
4. **没有公开的评测/诊断面板**：sticker_kit 的 `/sticker status`（档位、概率、冷却、最近协议注入与标签命中时间）、Diana 的事件中心（为什么回/为什么没回）、smart_imagechat_hub 的调试模式（逐步日志），都能回答"这次为什么没发图"；甲方需要类似的**决策链路日志**（意图标签 → 门控哪一层拒绝 → 候选 8 张是什么 → Writer 选了谁/弃选），否则调参靠猜。
5. **门控维度虽多但缺少"语境置信度"**：meme_manager / sticker_kit 都有"匹配分数低于门槛就不发"（min_score 0.45 / min_margin），甲方 8 张候选全靠随机，没有"这批候选到底配不配当前语境"的量化判断。
6. **没有点名豁免的显式设计**：所有调研项目都有"用户说'发个表情包'就跳过概率/冷却"；甲方是否支持需要确认，若无，用户主动要图时可能被门控拦掉。
