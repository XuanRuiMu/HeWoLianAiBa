# 表情包标注规范 V2（AI 视觉重标注版）

> 版本：2026-11-19 V2
> 适用：存量约 1.9 万张表情包的全量重标注（逐张看图重写）
> 唯一标注语言：简体中文
> 面向执行者：deepseek-v4.1-flash（具备图像理解能力）

---

## 一、这份规范要干什么

表情包在聊天里承担的是「用图替一句话」的功能。AI（写手）在生成回复时**看不到图片本身**，只能看到每张图对应的标注文字。所以标注写不好，这张图等于白发。

本次任务对全库逐张处理，每张图产生一个同名 `.json` 标注文件，完成三件事：

1. **重写标注**：根据图片真实内容与风格，重写描述、情绪、场景等字段；
2. **重命名**：根据内容与风格更新表情包名字（图片文件名 + 短名）；
3. **剔除垃圾**：图片不属于表情包范畴、或意义不明不知何时该发的，标记剔除。

## 二、处理对象与输出格式

### 2.1 输入

- 图片目录：`表情包/`（第一层，共约 19,318 张：.jpg 12,585 / .gif 4,414 / .png 1,941 / .webp 378）
- 已存在 109 个 `wx_*.json`（微信原生小表情，共 109 个 emoji）——**这 109 个 `wx_` 开头的图片不在本次重命名范围内**，但同样需要按本规范重写标注内容（原标注把「微笑」标成「无语」这类错误要修正）。
- 同名 `.json` 已存在时，直接覆盖重写。

### 2.2 输出：每张图一个同名 JSON

```json
{
  "短名": "熊猫头摊手",
  "描述": "熊猫头无奈摊手，配字'我也没办法'，用来接没辙的场面",
  "情绪标签": "无语",
  "适用场景": "对方说了让人接不下去的话时垫场；自己被将住时用来自嘲",
  "启用": true,
  "风格": "梗图",
  "关系阶段下限": "认识"
}
```

- 字段全部为中文 key，共 7 个，一个都不能漏。
- 图片主名改成什么（新文件名），就把 JSON 文件主名改成一样的；例：`旧名.png` 重命名为 `熊猫头摊手.png`，则标注文件为 `熊猫头摊手.json`。
- **不要输出任何多余的字段**（不要加「歧义度」「来源」之类）。

### 2.3 剔除标记：不产出 JSON，改为产出剔除清单

判定为「无意义」的图，**不写 JSON**，改为把文件名追加到剔除清单文件：

`表情包实验室/剔除清单.txt`（每行一个文件名，UTF-8，只写文件名不写路径）

## 三、七个字段的硬规则

| 字段 | 必填 | 类型 | 上限 | 规则 |
|---|---|---|---|---|
| `短名` | **必填** | 字符串 | ≤30 字符 | 全库唯一；不能含 `[` `]` `【` `】` `:` `：` 和换行；纯中文/字母/数字/短横线；**是 AI 输出 `[贴纸:短名]` 时用的名字，必须一眼看懂** |
| `描述` | 必填 | 字符串 | ≤120 字符 | 用一句话说清「图上有什么 + 配字是什么 + 替哪句话」，不要只重复图上的文字 |
| `情绪标签` | 必填 | 字符串 | ≤30 字符 | 只能从 12 个白名单里选一个（见 3.1） |
| `适用场景` | 必填 | 字符串 | ≤120 字符 | 描述「什么时候适合发这张」，要具体到聊天语境 |
| `启用` | 必填 | 布尔 | — | 一律 `true`（剔除的图不写 JSON） |
| `风格` | 必填 | 字符串 | ≤30 字符 | 只能从 4 个白名单里选一个（见 3.2） |
| `关系阶段下限` | 必填 | 字符串 | ≤30 字符 | 只能从 10 档里选（见 3.3） |

### 3.1 情绪标签（12 个，只能选一个）

`好笑`、`感动`、`无语`、`赞同`、`撒娇`、`安慰`、`庆祝`、`破冰`、`告别`、`卖萌`、`生气`、`委屈`

- 只选**最主导**的那一个。一张图可以同时让人笑又无语时，选更主导的。
- 判断口诀：**「这张图替 AI 说出哪句话」**——「笑死我了」→ 好笑；「你说得对」→ 赞同；「我不管我不管」→ 撒娇；「抱抱你」→ 安慰。
- **旧库重灾区**：1.4 万/1.9 万条被标成「无语」，绝大多数是错的。这张图如果让人「想笑/觉得好玩」就是好笑，只有真正表达「无奈、翻白眼、说不出话」才是无语。

### 3.2 风格（4 个，只能选一个）

| 值 | 含义 | 判定标准 |
|---|---|---|
| `黄脸` | 系统圆脸、笑脸、经典表情 | 微信/QQ 小黄脸、emoji 表情、圆脸卡通脸 |
| `祝福` | 花草风景、早安图、祝福大字图 | 风景/花朵/日出 + 「早上好/天天开心/平安喜乐」类大字 |
| `日常` | 温和的生活化贴图 | 真人/宠物/美食/生活照 + 简短配字，语气温和 |
| `梗图` | 网络梗、自嘲、拼贴、沙雕、斗图类 | 熊猫头、金馆长、暴漫、meme 拼贴、大字喊话、夸张搞怪 |

- 45 岁以上人设**只会拿到黄脸/祝福/日常**（梗图不给），所以「大字喊话式的暴力/粗口梗图」一律归 `梗图`，不要归 `日常`。

### 3.3 关系阶段下限（10 档，按序取）

`冷淡`(0) < `疏远`(1) < `认识`(2) < `熟悉`(3) < `朋友`(4) < `好友`(5) < `暧昧`(6) < `心动`(7) < `热恋`(8) < `深爱`(9)

规则：
- **默认全部填 `认识`**（从第 2 档起解锁）。关系阶段达到「认识」之后这张图就有资格进候选。
- 只有满足以下条件才填更高档：
  - 含**亲亲/抱抱/爱心/么么哒/情侣/暧昧挑逗**含义 → `暧昧`
  - 含**粗口、性暗示、极端重口、过于亲密的私密梗** → `心动` 或 `热恋`（保守就填 `心动`）
  - 含**只有情侣才懂的私密/撒娇/负距离梗** → `热恋`
- 宁低勿高：填高了这张图永远出不来；填低了最坏只是早几档出现。

## 四、短名与重命名规则

### 4.1 短名怎么起

1. **必须是「看一眼就知道什么意思」的中文短语**，≤30 字符（实际建议 3–8 字）。
2. 优先用「主体 + 动作/情绪」结构：`熊猫头摊手`、`猫猫流泪`、`金馆长大笑`、`柴犬疑惑`、`狗头保命`。
3. 主体优先用「角色/来源」：`熊猫头`/`金馆长`/`柴犬`/`猫猫`/`兔子/龙图`/`蘑菇头`/`暴漫`/`小黄脸`。
4. 动作或情绪取图上最突出的：`摊手/大笑/流泪/疑惑/鼓掌/生气/比心/鼓掌/吃瓜/装死/得意/害羞/翻白眼`。
5. 图上有**经典配字**的，短名要带上那个配字的意思：`雨女无瓜`、`栓Q`、`听我说谢谢你`、`退退退`。
6. 同一个角色/同一系列，前缀保持一致：`熊猫头摊手`、`熊猫头流泪`、`熊猫头吃瓜`。
7. **禁止**：纯数字、纯标点、`无意义`、`表情`、`图片`、`未命名`、`其他` 这类没信息量的名字；也禁止和图意不符的名字（如把摊手叫「微笑」）。

### 4.2 文件名怎么改

- 文件名 = 短名 + 原扩展名（保持原扩展名不变）。例：短名「熊猫头摊手」，原文件 `x123.jpg` → 改名 `熊猫头摊手.jpg`。
- 4.3 的保留规则优先：**已经起好、贴切的旧名不改**，只改名字烂的。
- 重命名后，同名 `.json` 的主名要跟着改。**改完必须保证：短名 == 文件主名**。
- 全库唯一：如果重命名撞名（两张图算出同一个短名），第二张加序号：`熊猫头摊手2`、`熊猫头摊手3`。
- **不用重命名的情形**（原样保留、不动）：
  - `wx_` 开头的 109 个微信原生表情（`wx_微笑.png` 等，主名即短名，保持不动）；
  - 旧名本来就是干净贴切的中文短名（如 `金馆长 4.gif`、`绝对不行.gif`）——只在原文件名明显是「乱码/编号/下载站残渣/错别字/超长垃圾串」时才改。

### 4.3 重命名的判断标准（什么样的名字必须改）

必须改：
1. 文件名是一串无意义编号：`IMG_1234`、`mmexport123456`、`tx123`、`未命名`、`新建文件夹(3)` 等；
2. 文件名是下载站残留：`【高清】xxx表情包-第3弹-某某网.jpg`、`xxx表情包图片大全 2.jpg` 等带站点/合辑信息的；
3. 文件名和图意不符（文件名说「开心」图上是摊手无奈）；
4. 文件名太长（>15 字符）或带乱码、带特殊字符。

不用改：
1. 文件名已经是干净的中文短名（≤15 字符、无乱码、无站点残留）；
2. `wx_` 开头的原生表情。

## 五、剔除规则（判定「不是有效表情包」的图）

命中以下**任意一条**，写入剔除清单，不产出 JSON：

1. **非表情包范畴**：
   - 普通照片/风景照/证件照/截图/海报/表情包合辑拼图（一张图里塞了十几个表情的「大全」图）；
   - 纯文字大字报（只有一句口号/一句文案，没有任何角色或画面）；
   - 纯 logo、广告图、二维码、活动宣传图。
2. **意义不明，不知道什么时候该发**：
   - 画面内容无法判断在表达什么情绪或语境；
   - 无任何可读配字且画面抽象/混乱，标注者看了也不知道它在说什么；
   - 图上文字糊成一团/被遮挡，无法辨认图意。
3. **低质量不可用**：
   - 画面严重模糊、大面积马赛克、几乎全黑/全白、内容被裁切得看不出主体；
   - 图片文件损坏（打不开/半截图）。
4. **违规内容**（不要标、不要改名、直接剔除）：
   - 色情、裸露、性行为的图片；
   - 血腥、暴力伤害、虐待、尸体等画面；
   - 其他明显不适宜出现在恋爱聊天场景的内容。

**注意**：粗口/沙雕/阴阳怪气但属于正常网络梗文化的图（如熊猫头骂人类、金馆长阴阳怪气），**不算违规，保留**。

## 六、执行要求（给写提示词的你 / 执行标注的 AI）

1. **逐张看图**：必须对每张图片实际打开、用视觉能力理解，禁止只读文件名或旧 JSON 猜内容。
2. **每张图一条记录**：要么产出一条 JSON（7 字段），要么写入剔除清单。
3. **描述和场景必须具体**：描述要说清「图上有什么+配字+替哪句话」；场景要具体到聊天语境（如「对方说晚安时」「被夸时」「自己说错话时」），不要写「任何场合」这种空话。
4. **情绪标签分布要真实**：禁止偷懒全标同一个（旧库 74% 都标成「无语」是反面教材）。全库各标签的分布应与真实聊天频率大致相符：好笑/赞同/卖萌/安慰/破冰 应占大头；无语/生气/委屈/告别 是少数。
5. **短名全库唯一**：重命名或撞名时按 4.2 处理。
6. **大小与性能**：单条处理建议 ≤3 秒；批量任务应支持断点续跑（已处理过的文件跳过）。
7. **进度与日志**：每处理 N 张输出一次进度；记录三类计数：已产出 JSON 数 / 已重命名数 / 已剔除数。
8. **不改动图片内容**：只允许改名，不允许裁剪、转码、覆盖图片内容。

## 八、验收标准

- 每张保留下来的图都有同名 JSON，7 字段齐全、取值合法（情绪/风格/关系阶段都在白名单内）；
- 剔除的图进入剔除清单，清单条数 + JSON 条数 ≈ 图片总数；
- 抽查 50 张：短名与图意相符、描述具体、情绪标签合理、场景不空泛；
- 情绪标签整体分布不再畸形（无语占比降到 15% 以下）；
- 无重名、无禁用字符、无超长字段；
- 原文件名被改的，短名 == 新文件主名。
