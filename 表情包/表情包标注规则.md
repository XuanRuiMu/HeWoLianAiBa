# 表情包标注规则

本文件是**添加新表情包时必须遵守的规则**。每加一张图，必须在同一目录建一个同名的标注文件，按本规则填满字段。系统不读图片内容，AI 只靠标注里的文字理解这张图，所以标注写错，图就等于白发。

适用范围：仓库根目录 `表情包/`。线上服务器对应 `/opt/lianaiba/表情包/`，两边要各放一份。

---

## 一、文件怎么放

| 项目 | 规则 |
|---|---|
| 目录 | `表情包/` 第一层。**不扫描子文件夹**，放进子目录的图不会被读到 |
| 图片后缀 | `.png`、`.jpg`、`.jpeg`、`.gif`、`.webp`，后缀不区分大小写 |
| 标注文件 | 与图片**主名完全一致**的同名 `.json`，例如 `mao-01.png` 必须配 `mao-01.json`。`.json` 必须小写；主名大小写不一致会配对失败 |
| 图片大小 | 大于 0 字节、且不超过 **6 MiB（6291456 字节）**。可用环境变量 `BIAO_QING_BAO_ZUI_DA_WEN_JIAN_ZI_JIE` 覆盖，允许范围 1 KiB–100 MiB |
| 建议尺寸 | 512 × 512 正方形 PNG。前端按方形气泡显示，超出部分等比缩放 |
| 图片内容 | 每张图字节必须不同。内容完全相同的两张图会让校验值撞车，影响老消息回退 |
| 生效时间 | 目录内容变化后自动重扫，最短比对间隔默认 2000 毫秒，探测缓存默认 30000 毫秒。**不用重启服务** |

---

## 二、标注文件的 7 个字段

key 全部是中文，大小写敏感。除「短名」外都可以不写，但**建议全部写全**。

| 字段 | 必填 | 类型 | 长度上限 | 不写时 | 写错时 |
|---|---|---|---|---|---|
| `短名` | **必填** | 字符串 | 30 个字符 | **整张图不进图库** | 非字符串、空白、含控制字符、含 `[` `]` `【` `】` `:` `：` 中任意一个 → **整张图不进图库** |
| `描述` | 否 | 字符串 | 120 个字符 | 空，候选块显示「无」 | 非字符串按空处理；超长截断并打警告 |
| `情绪标签` | 否 | 字符串 | 30 个字符 | 记为「待打标」 | 不在下面 12 个白名单里 → 记为「待打标」并打警告 |
| `适用场景` | 否 | 字符串 | 120 个字符 | 空，候选块显示「通用」 | 非字符串按空处理；超长截断并打警告 |
| `启用` | 否 | 布尔 `true`/`false` | — | `true` | 非布尔按 `true` 处理并打警告 |
| `风格` | 否 | 字符串 | 30 个字符 | 「日常」 | 不在下面 4 个白名单里 → 归为「日常」并打警告 |
| `关系阶段下限` | 否 | 字符串 | 30 个字符 | 不限制（序号 0，任何阶段都可能出） | 不在下面 10 档里 → **按序号 9「深爱」处理**（几乎不出现）并打警告 |

**特别注意**：`短名` 是 AI 输出标记 `[贴纸:短名]` 时用的名字，也是后端查图的唯一依据。要短、好认、能表意，全库不能重复。两张图用了同一个短名，**这两张都会失效**。

## 三、三个白名单

### 情绪标签（12 个，只能选一个）

`好笑`、`感动`、`无语`、`赞同`、`撒娇`、`安慰`、`庆祝`、`破冰`、`告别`、`卖萌`、`生气`、`委屈`

导演给出本轮心情底色后，系统按「情绪标签等于该词」或「适用场景里包含该词」筛候选。所以想让某张图在「好笑」时更容易被选中，可以把「好笑」两个字写进 `适用场景`。

### 风格（4 个，只能选一个）

| 值 | 含义 |
|---|---|
| `黄脸` | 系统圆脸、笑脸、经典表情 |
| `祝福` | 花草风景、早安图、祝福大字图 |
| `日常` | 温和的生活化贴图（**默认值**） |
| `梗图` | 网络梗、自嘲、拼贴、沙雕、斗图类 |

风格决定**哪些人设能拿到这张图**：

| 人设年龄 | 允许的风格 |
|---|---|
| 10–44 岁 | 黄脸、祝福、日常、梗图 |
| 45–59 岁 | 黄脸、祝福、日常 |
| 60–99 岁 | 黄脸、祝福、日常 |

### 关系阶段下限（10 档，写中文名或拼音键都行）

| 序号 | 中文 | 键 | 序号 | 中文 | 键 |
|---|---|---|---|---|---|
| 0 | 冷淡 | `lengDan` | 5 | 好友 | `haoYou` |
| 1 | 疏远 | `shuYuan` | 6 | 暧昧 | `aiMei` |
| 2 | 认识 | `renShi` | 7 | 心动 | `xinDong` |
| 3 | 熟悉 | `shuXi` | 8 | 热恋 | `reLian` |
| 4 | 朋友 | `pengYou` | 9 | 深爱 | `shenAi` |

只有当前关系阶段序号 **≥** 这张图的下限，它才会出现在候选里。想做「关系够深才解锁的专属梗图」，就在这里填 `暧昧` 或更高。

## 四、可直接复制的模板

文件名示例：`mao-01.png` 与 `mao-01.json`

```json
{
  "短名": "猫猫摊手",
  "描述": "橘猫摊手一脸无奈，用来接住没话说或有点无语的场面",
  "情绪标签": "无语",
  "适用场景": "话题接不下去时垫场，也接得住好笑的自嘲",
  "启用": true,
  "风格": "日常",
  "关系阶段下限": "认识"
}
```

`描述` 和 `适用场景` 会原样出现在给 AI 的候选清单里，格式是 `描述:… | 情绪:… | 场景:…`。写清楚「这张图能替哪句话」，不要只重复图上已有的文字。

## 五、加一张新图的操作清单

1. 图片放进 `表情包/` 第一层，主名用小写英文/数字/短横线（如 `mao-01.png`），不要用中文、空格或特殊符号。
2. 同目录建同名 `.json`，按第四节模板填 **7 个字段**，一个都别漏。
3. 检查 `短名` 全库唯一、不含禁用字符。
4. 本地验证（在 `HouDuan` 目录执行）：

   ```bash
   npx ts-node --transpile-only -e "const k=require('./src/services/表情包库');(async()=>{const a=await k.quQuanBuQiYong();console.log('总条目',a.length);for(const x of a)console.log(x.duanMing,'|',x.fengGe,'|',x.guanXiJieDuanXiaXian)})()"
   ```

   条目数应等于图片数，且每张的风格、关系下限与标注一致。
5. 把图片和 json 一起 `git add` 提交，否则换机器或服务器看不到。
6. 服务器也要放一份到 `/opt/lianaiba/表情包/`，属主 `lianaiba:lianaiba`、文件权限 `644`、目录权限 `755`。约 2 秒自动生效，不用重启。

## 六、常见错误与后果

| 错误 | 后果 |
|---|---|
| 只放图片、不写 json | 用**文件名**当短名，情绪「待打标」、风格「日常」、关系无限制。图能发，但 AI 完全不知道它什么意思 |
| json 里漏写 `短名`、写成数字、或只写空格 | **整张图不进图库** |
| 短名含 `:` `：` `[` `]` `【` `】` | **整张图不进图库** |
| 两张图短名相同 | **两张都不进图库** |
| `情绪标签` 写成白名单外的词 | 归「待打标」，导演按情绪筛时永远筛不到它 |
| `关系阶段下限` 打错字（如「暧味」） | 按「深爱」处理，几乎不会出现 |
| `.json` 写成 `.JSON`，或主名大小写不一致 | 配对失败，退化成「用文件名当短名」 |
| 图片放进子文件夹 | 完全扫不到 |
| 图片超过 6 MiB 或 0 字节 | 跳过，不进图库 |
| 只改本地、忘了服务器 | 线上仍看不到这张图 |

## 七、这些字段最终怎么影响发送

1. 每轮最多 **1 张**图片表情包，这是代码里的硬上限，不因标注改变。
2. 一轮里 AI 最多看到 **8 张**候选（默认，可由 `BIAO_QING_BAO_HOU_XUAN_SHU_LIANG` 配成 1–50），从符合下面条件的图里**随机**抽，不是按贴合度排序。
3. 一张图要出现在候选里，必须同时满足：
   - `启用` 为 `true`；
   - `风格` 在当前人设年龄档允许的列表里；
   - 当前关系阶段序号 ≥ `关系阶段下限`；
   - 若导演给了本轮心情底色，还要通过「情绪标签相等 / 适用场景包含」这一关；导演没给底色时不加这一条。
4. 系统先判断**这一轮要不要给候选**（看人设、关系、聊天节奏、是否深夜、是否危机、对方是否刚发图），再按上面筛图。所以标注写得再好，也只决定「有资格的是哪几张」，不决定「这轮一定发」。
5. 发不发、图放在哪句话的前后、还是只发图不写字，由 AI 自己按语境决定。
