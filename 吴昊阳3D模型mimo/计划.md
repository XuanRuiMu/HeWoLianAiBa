## 一、需求

登录页草地背景中，吴昊阳**趴在草坪上、手中拿着手机看**，默认视角效果对齐 `吴昊阳2D图片.png`。位置固定在地形某点，相机任意转动（含引擎 lookAround 漂移）都不漂移、不穿帮。也就是说，最后最核心的目标，就是现在默认视角下，与吴昊阳2D图片一模一样！经过其他AI验证，原模型过于粗糙，2D图片无论如何都做不出3D的效果。虽然我不需要你100%还原图片，但是，我要求你，最后的建模的结果必须是一个标准的人形的！且没有任何地方出现像素模糊等低级错误。所有角度都必须完美无瑕！在此基础上，尽可能还原2D图片的样子。

融合要求：对象存在于引擎 `scene` 内（吃引擎光照与后处理）、与场景同色温、有接地阴影、能被前景草遮挡。

## 三、引擎实测事实

1. **跨实例不兼容**：用父页 r128 的类（`window.parent.THREE` 下的 `Mesh`/`MeshBasicMaterial` 等）创建对象挂进引擎场景，材质会被渲染器丢弃——对象存在、属性正常、画面无像素。判定：`instanceof 父页类`。
2. **材质贴图时机**：引擎材质只在**构造参数**里处理 `map`；构造后 `material.map = tex` 渲染为空（T3 自建材质就是空参构造+事后赋值，长期不显示）。
3. **纹理类分多种**：`image = OffscreenCanvas` 类 / `image = Object`（DataTexture）类 / `image = HTMLImageElement` 类；混用会渲染为空或灰白。
4. **引擎官方纹理加载路径**（读 `resources.loadTextureOriginal` 源码）：`new 引擎纹理类(OffscreenCanvas)` → `flipY = true` → `needsUpdate = true`。`registerGeneratedTexture(name, texture)` 用于注册"生成类"资源；`loadSource` 对 `type === 'generated'` 会抛错要求改用前者。
5. **健康监测**：`grass-bg.html` 内 T3 主道路块每 60 帧检查自己的平面是否还在场景；被移除会降级并进入重证明循环 → 画面高频闪烁。
6. **可用开关**：`window.__wuTieTuUrl` 覆盖 T3 贴图地址；`window.__wuTieDiMaoDing = true` 让 T3 停止逐帧 billboard（交出朝向控制权）。
7. **既有噪音**（勿误判为新 bug）：粒子系统 `TypeError ... reading 'length'` @ `g5.addSamplingWeights`；遮挡剔除 PBO 性能警告。
8. **地形与相机**：地形网格名 `main-island`；登录页相机位约 `(5.75, 1.34, 5.27)`；草叶层高约 `0.06~0.18`。

## 五、验证坑

1. **引擎相机不可手动冻结**：手动改 `camera.position/quaternion` 会被引擎每帧覆盖，据此截图会误判"角色不可见"。要确认是否在画面内：`cam.updateMatrixWorld(true)` 后 `position.clone().project(cam)` 求 NDC，或把角色移到「屏幕中心射线命中的地形顶面点」再截图。
2. **帧间差分不可靠**：风草/粒子/水面导致两帧差异可达 6–8%。
3. **判断是否真在渲染**：临时把材质换成纯色——可见则链路正常，问题在材质/贴图。
4. **判断是否闪烁**：连续采样接管状态与可见性 ≥12 次，应完全一致。
5. **Playwright**：`executablePath: C:/Users/xuanr/AppData/Local/ms-playwright/chromium-1234/chrome-win64/chrome.exe`（本机缓存仅 1228/1234）。iframe 内无 `THREE`（父页提供），注入 loader 前先 `iframe.contentWindow.THREE = parent.THREE`。
6. **昼夜**：登录页配色随昼夜变化（夜景=紫粉草地+深蓝星空；白天=金黄草地+青绿树），两种都要看。
